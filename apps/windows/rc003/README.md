# 无线麦 — Windows client（小米遥控器2 Pro）

> **状态：`1.0.44` 正式发布源码。** 本目录包含跨平台协议测试，以及针对 WinRT BLE、
> Raw Input、SendInput 和 PortAudio 的 Windows CI/构建流程。对应的 candidate.44
> 已完成小米遥控器2 Pro 连接、按键映射和语音输入实测；CI 仍不能替代真实设备、
> 输入法、长期运行和不同 Windows 环境中的继续验证。
> 当前产物未签名，也不会自动安装虚拟音频驱动。完整冻结包会带入固定版本、固定
> 哈希的 Frida Gadget 和独立 HID 管理员助手；安装或更新该助手时请求 UAC，主程序和
> 随 Windows 启动以普通权限为目标。每个登录会话只有一个长期主进程，遥控器服务和
> 元素导航都由该进程持有。VB-CABLE 仍是需要用户明确安装的
> 可选第三方组件（见下文）。

这是本仓库独立维护的 Windows 客户端，面向小米遥控器2 Pro（内部型号 RC003），
提供按键映射和 ATVV
（Android TV Voice-over-BLE）语音桥接。项目整体说明请阅读仓库根目录的
`README.md`。

维护者需要先阅读 `WINDOWS-ARCHITECTURE-LEDGER.md`。它集中说明项目背景、
当前范围、Windows 版的进程、线程、BLE/ATVV、Raw Input、Frida、音频、配置、
安装和验证边界；具体故障和批次证据再分别查阅 `bugs/`、`MAINTENANCE.md`
与 `reviews/`。性能基线、已确认性能问题和优化顺序统一查阅
[`PERFORMANCE.md`](PERFORMANCE.md)。

需要决定是否进入完整检查、本地测试包、候选、正式发布、复用已有结果，或长任务
确需分阶段和安排复核批次时，读取
[`VALIDATION-AND-DELIVERY.md`](VALIDATION-AND-DELIVERY.md)。本文只提供实际命令和
使用入口；普通定向检查不需要先读专项，命令存在也不表示每次修改都必须执行。

设置窗口当前只提供 **小米遥控器2 Pro**，使用桥接、虚拟输出和 13 键映射界面。
DJI Mic 2 不再出现在当前设备选择和自动诊断中；既有设备档案与底层识别代码仅作
旧配置兼容，不属于当前用户功能。

### 系统要求

- Windows 10 1809（内部版本 17763）或以上，64 位；
- 未签名安装包/可执行文件：首次运行时 Windows SmartScreen 可能提示
  "Windows 已保护你的电脑"——这是预期行为，不是错误，本项目目前没有代码
  签名证书。

  在点击"仍要运行"之前，建议先核对文件的 SHA-256 校验值是否与同一次构建
  产出的 `SHA256SUMS.txt` 一致。以 PowerShell 为例：

  ```powershell
  Get-FileHash -Algorithm SHA256 .\RemoteMicRC003-<版本号>-portable-unsigned.zip
  ```

  把输出的 `Hash` 值（不区分大小写）与 `SHA256SUMS.txt` 中同一个文件名那
  一行的哈希值逐字比较；只要有一个字符不一致就不要运行，重新下载或联系
  发布者核实。核对一致后，再点击 SmartScreen 提示中的"更多信息"，然后点击
  "仍要运行"。

### 程序内手动检查更新

“设备”页“检查更新”一行提供“使用方法”链接和“检查更新”按钮，链接打开本项目 GitHub 首页介绍。程序只在用户点击后访问固定的
`ZSTDJan/windows-remote-mic-app` GitHub Releases，不会在启动时或后台自动检查，
也不会在程序中保存 GitHub 账号或令牌。它按发布资产文件名里的内部版本比较，
不会把仓库 tag 当作程序版本；若最新版本的文件尚未上传完整，会直接提示重试，
不会退回并推荐旧版本。

发现新版后，便携版或源码运行下载便携 ZIP。新 Release 不带安装器时，旧安装版入口也下载
免安装 ZIP，并提示解压到新的文件夹使用；历史 Release 仍带安装器时保持旧格式兼容。
程序会先读取同一次 Release 的 `SHA256SUMS.txt`，核对文件名、大小和 SHA-256；
GitHub 提供资产摘要时也会一并核对。下载先写入 `.part` 临时文件，取消、中断或
校验失败会清理临时文件，完整通过后才改为正式文件名。文件保存在
`%LOCALAPPDATA%\RemoteMic\RC003\updates\<版本号>`。下载新版前会清理更旧的程序缓存；
升级后首次运行会清理当前及更旧版本的程序缓存，陌生文件和链接不会删除。

程序不会自动运行下载文件、关闭当前版本或覆盖安装目录。下载完成后点击“打开文件夹”，
先完全退出无线麦，再把免安装 ZIP 解压到新的文件夹使用；仅历史安装版更新才手动运行安装器。

### 安装

当前请使用免安装版。安装器说明仅为历史版本维护保留；两种方式分别说明如下；
后面"首次使用、停止/重启、卸载"一节也会按这两种方式分别给出步骤。

**方式一：安装器（提供 Start Menu 入口）**

运行安装器：主程序只安装到当前用户目录，不替用户启用开机自动启动，也不安装任何
驱动。文件安装完成后会出现一次 UAC，用于把独立 HID 助手写入 Program Files 并登记
固定的按需计划任务；确认后，日常启动、桥接和随 Windows 启动都不再弹 UAC。若取消，
全部自定义按键映射停用，只保留 Windows 原始按键操作，设置页“按键接收”行可点
“修复权限”重试。安装完成页默认勾选打开当前新版本；需要登录后自动运行时，由用户在
“设备”页底部明确开启“随 Windows 启动”。Start Menu 分组提供程序主入口、设置入口、
停止和卸载；主入口与桌面快捷方式打开同一个桌面程序，任务栏图标和窗口一一对应。
是否在程序打开后自动执行一次“启动服务”，由独立的“启动程序时自动运行服务”选项决定。
当前预授权任务要求正在登录的 Windows 账号本身属于管理员组；标准账号临时输入另一个
管理员账号的密码，不会让该任务归属当前标准账号，因此不属于当前支持路径。

覆盖安装新版时，安装器在写入任何程序文件前先请求旧版完整退出。当前版本的按键映射
会自动保存；只有编辑弹窗尚未完成、自动保存失败或仍有其它未保存设置时，才会恢复旧窗口
让用户选择保存或放弃。旧的双进程版本会先正常停止遥控器
服务，再把可能已经隐藏的设置窗口唤到前台，提示用户从通知区域选择“完全退出”。安装器
不会强杀旧设置窗口，避免丢掉尚未完成或自动保存失败的按键修改。无法确认安全退出、用户没有处理保存
提示或退出超时时，安装会直接停止。只有旧程序本身以管理员身份运行、
普通权限无法核实时，关闭旧版这一步才会额外请求一次 UAC；取消后安装保持未开始状态。
如果另一个文件夹中的便携版仍在运行，安装器也会唤出旧窗口并停止安装，避免安装完成后
又被旧实例拦截、实际打开的仍是旧版；完全退出旧便携版后在安装器中重试即可。
升级会完整替换程序目录中的 PyInstaller 运行文件，但保留
`%LOCALAPPDATA%\RemoteMic\RC003` 下的设置、日志和采集数据。

**方式二：便携版 ZIP（解压即用，没有 Start Menu 入口）**

把便携版 ZIP 解压到你自己选择的目录：解压本身不请求管理员权限，也不安装任何驱动，
不写入 Start Menu 或桌面快捷方式，也不会在解压时自动设置开机启动。解压目录根层
只保留一个供用户启动的程序 `RemoteMicRC003.exe`；管理员按键组件位于 `_internal`
内部目录，只由程序自动调用，不需要也不应手动打开。便携版
**没有**安装器提供的程序、设置、停止和卸载 Start Menu 入口，也没有打包停止脚本
或卸载程序；仍可在程序“设备”页底部明确开启随 Windows 启动，但之后移动或删除解压目录
会让该启动项失效。首次启用自定义按键映射时，便携版会先询问，再通过一次 UAC 安装或更新
共享的预授权 HID 助手；成功后主程序、日常启动和随 Windows 启动都保持普通权限，
不再反复弹 UAC。取消或失败时全部自定义按键映射停用，只保留 Windows 原始按键操作，可在“设备”页
“按键接收”一行点击“启用改键”重试。当前登录账号需要本身属于管理员组；标准账号
临时输入另一个管理员账号的密码不属于支持路径。具体步骤见下一节“便携版 ZIP 用户”。

当前源码会识别并更新旧助手，沿用上述一次授权流程；取消更新时保留 Windows 原始按键。
新版按键脚本支持热重载。旧组件仍驻留时，程序会先确认遥控器独占且在线，再尝试单独
重载其驱动并重新连接，不要求用户先重启电脑。若无法安全重载，仍显示“请重启电脑”；
此时保存工作后重启 Windows，再打开新版。仅重启无线麦服务不能清除旧版驻留组件。
已有 `candidate.31/32` ZIP 不包含本次热重载修复，实测步骤见 `CHECK-HID-RELOAD-001`。

双击便携版时，如果其它目录或旧版本的无线麦正在运行，程序会明确询问是否切换。
同一副本重复双击只恢复现有窗口；确认切换后，支持完整退出请求的旧版会自行处理未保存
提示并正常退出；更早版本 5 秒内没有接收请求时，当前版本会立即提示用户从通知区域
选择“完全退出”，不会再无窗口等待到最终超时。旧版完全退出后，同一次双击会继续打开
当前便携版。程序不会强杀旧版；取消、超时、退出状态或切换请求无法安全确认时，当前
便携版不会启动。

### 配对小米遥控器2 Pro

1. 同时长按遥控器的【主页键】+【菜单键】，直到遥控器进入配对广播状态；
2. 打开 Windows"设置 → 蓝牙和其他设备"，等待遥控器出现后完成配对；
3. 程序按蓝牙名称自动查找已配对设备，不需要手动输入地址；找到 0 个或
   超过 1 个匹配设备时会拒绝猜测并报错退出，而不是随意连接一个。

### 选择要使用的遥控器（当前源码）

设备页第一行点击“选择设备”，弹窗标题旁显示当前使用的设备；两行分别是
“已添加设备”和“已配对设备”，每行横排名称、下拉框和操作按钮。
在 Windows 已配对列表中选中遥控器并点“添加设备”，
再在已添加列表中点“使用此设备”。添加本身不会切换设备。软件记住具体的一只，
按键、真实检测和语音都跟随它；断线只重连这一只，不按名称或枚举顺序换用其它遥控器。
旧配置首次使用此功能也需明确选择，已有按键映射和语音设置保留。

切换会先结束旧按键和录音；原服务在运行才恢复运行，原来停止则继续停止。
“移除设备”只清软件记录；移除当前设备会停止服务，不删除 Windows 蓝牙配对。
目前只适配小米遥控器2 Pro，未适配型号显示不可添加，Chromecast 不因出现在列表中就获得支持。

两只设备共用 Windows 驱动进程时，当前源码先核对提交按键的设备对象，只处理所选的
实体遥控器；另一只先按或按同一个键都不能占用它的接收通道。无法核实来源时显示
“按键来源待区分”，保留接收连接等待恢复，不因此反复重启服务。
这与旧组件升级分开判断：支持热更新的组件直接更新；旧非热更新组件仍在共享进程中时，
无法安全单独迁移的限制仍保留，可能需要一次电脑重启。程序不会强杀共享系统进程。
既有 candidate.33 不含本节功能；本地测试包状态见 `TESTING.md` 的 `CHECK-DESKTOP-028`，
功能验证边界见 `CHECK-DEVICE-SELECT-001` 及 `CHECK-HID-SOURCE-001`。

### （可选）安装 VB-CABLE 作为虚拟麦克风

本程序不会自动下载、安装、启用或卸载任何虚拟音频驱动，也不会修改
Windows 默认输入/输出设备。如果要让语音识别/听写软件把 RC003 的语音当作
一个"麦克风"使用，需要自行从 VB-Audio 官方网站下载并安装官方
[VB-CABLE](https://vb-audio.com/Cable/)，然后按下面的方向手动配置——
方向不能弄反：

- 无线麦“语音”页的“输出端点”（语音输出设备） → 优先选择
  `CABLE Input — Windows WASAPI`，没有 WASAPI 时可选
  `CABLE Input — Windows DirectSound`（VB-CABLE 虚拟"扬声器"一侧）；
- 语音识别/听写软件的麦克风输入设置 → 选择 `CABLE Output`
  （VB-CABLE 虚拟"麦克风"一侧）。

不要选择 `Windows WDM-KS` 视图：PortAudio 能枚举它，但当前阻塞播放 API
不能打开它。新版本会隐藏并拒绝该视图，保存前还会实际打开一次端点。两边
选成同一个名字，或方向选反，都会让语音功能失败，但普通按键映射仍然正常。

**一键随包安装（XRBM-031，可选）**：打开设置窗口“语音”页，“虚拟音频”一行会
显示 CABLE Input/CABLE Output 两个端点当前是否存在。点击“安装音频”会先
弹出一个说明对话框
（VB-CABLE by VB-Audio，独立 Donationware，非 GPL 项目代码，可自愿捐赠/
购买授权，仅随包提供基础版、不含付费的 A+B/C+D，安装会改变系统状态并需要
重启），确认后才会解压随安装包携带的官方 `VBCABLE_Driver_Pack45.zip`（构建
时已用固定的 SHA-256 校验过，未被本项目修改），并以 Windows 用户账户控制
(UAC) 提示启动官方原始的 `VBCABLE_Setup_x64.exe`——本程序自身全程不以管理员
身份运行，UAC 提示可以随时取消，取消不会安装任何内容。安装完成后需要重启
电脑，重启后回到“语音”页，程序会自动重新检查。只有当前没有使用推荐端点时，
第一行才显示“选推荐端点”；也可以直接在“输出端点”下拉选择。两种操作都会按
WASAPI、DirectSound 的顺序选择并预检，成功后自动保存和刷新页面状态，不需要再点
“应用”或回设备页“重新检查”。仍需要手动把
听写/识别软件的麦克风输入设为 `CABLE Output`）。这个入口只是把上面的手动
下载步骤换成随包、离线、显式确认的流程，效果完全一致；仍然可以选择直接从
<https://vb-audio.com/Cable/> 手动下载安装。

服务运行中更换输出端点后，保存只记录新选择；请到“设备”页点击出现的“重启服务”，
确认服务重新连接后再试说话。程序不会为这项设置自动打断正在进行的语音；保存失败
保留原选项，服务尚未运行时则在下次启动使用保存的输出端点。

普通按键映射和恢复默认可以在语音快捷键尚未配置时保存；话筒语音仍需到“语音”页
完成配置。启动语音程序时，程序会在后台等待启动结果，设置窗口保持响应；完成前
相关语音操作暂不可重复执行，取消或失败后可重试。

“麦克风隐私”只打开 Windows 麦克风权限页，供用户确认桌面语音软件可以访问
麦克风；程序不会把 `CABLE Output` 改成 Windows 默认麦克风，也不显示容易与
目标语音软件自身输入设备设置混淆的“声音输入”入口。

安装并选择端点后，需要排查声音传输时，可以在“语音”页“测试验证”的“虚拟声卡”
一行点击“检查虚拟声卡”。这是可选排查工具，平时说话不需要先点。
测试只在用户点击后运行；遥控器服务正在运行时会先要求确认，确认后
临时正常退出服务，测试结束再自动恢复。它会发送约一秒
合成扫频，并确认信号是否从 `CABLE Input` 到达同一音频接口下的
`CABLE Output`。测试不保存声音、不修改 Windows 默认设备，但正在监听
`CABLE Output` 的其它程序也可能收到这段测试信号。完整音频测试在一次性子进程
中运行；音频驱动调用卡住时会结束该测试进程，不让设置窗口退出无限等待。通过只
代表本地虚拟音频通道正常，不代表 RC003 已传声、输入法已开启或文字已经上屏。

“试输入”一行的“试说一句”只打开普通文本输入框，可以输入、清空和关闭。
是否成功以实际进入输入框的文字为准；这个入口不启动服务、不发送测试声音、
不因设备或上次语音状态更换按钮和显示红色提示。设备、服务和音频配置仍在各自
所在行处理。输入法在该窗口能否唤起仍取决于宿主兼容性，也可以在记事本中对照。

### 首次使用、停止/重启、卸载

打开程序后，“设备”页的当前设备只提供“小米遥控器2 Pro”，并在底部整组维护
随 Windows 启动、程序启动时自动执行一次“启动服务”和关闭窗口行为；“语音”页维护
CABLE 输出、语音程序和语音按键，“按键”页维护 13 键映射。旧配置
若曾保存 DJI Mic 2，本次运行会
按小米遥控器2 Pro 显示，但仅打开设置不会自动改写原配置。

“打开设置并选择语音输出端点”“设置按键映射”“手动确认已配置的语音组合键”这几步在
两种安装方式下目标一样，但具体怎么打开设置、怎么启动/停止/卸载不同
——安装器用户走 Start Menu，便携版用户在解压出的文件夹里用命令和任务
管理器，分别在下面两个小节说明。

**安装器用户**

1. 安装时确认一次管理员权限。若当时取消，“设备”页“按键接收”会明确显示
   “管理员按键组件异常”，点击同一行的“修复权限”并确认 UAC 即可补装；该操作不会
   把主程序改成管理员程序。当前登录账号需本身属于管理员组，不能用标准账号临时输入
   另一个管理员账号的密码代替。然后打开程序（Start Menu 中的“无线麦”或“无线麦 设置”），先在“设备”页检查
   小米遥控器2 Pro 和按键接收，再到“语音”
   页点击“选推荐端点”选择 CABLE Input，再选择语音程序和语音按键；端点下拉、
   语音程序和语音按键会各自自动保存。到“按键”页编辑映射时，弹窗点“完成”后也会
   自动保存，不再有单独的“保存映射”按钮；
2. 回到“设备”页点击“启动服务”运行遥控器服务。“设备”页的“启动服务”使用上次已经保存的
   设置，不会顺带保存其它页面尚未应用的修改。需要程序每次打开后自动运行服务时，
   在“设备”页底部开启“启动程序时自动运行服务”；它只在程序打开后执行一次，与
   “随 Windows 启动”互不绑定。遥控器服务一行会明确区分“点击‘启动服务’”、
   “正在连接遥控器”、“请按遥控器方向键”、“点击‘重新连接’”、已连接和启动失败等
   真实阶段；连接失败进入重试等待时会提示重新连接，不会继续误提示方向键。只有
   桥接运行状态确认设备连接后，界面才显示“小米遥控器2 Pro 已连接”；实际按键和语音是否
   可用仍需按下面步骤真机验证。运行中的服务还会报告版本来源、Raw Input、HID tap、
   最近按键和语音活动，并每 5 秒更新一次状态。设置页发现其它构建或两个按键通道都
   明确失败时，只在语音空闲时正常重启一次当前版本；旧状态或长时间不更新时只显示
   “重新启动”，不会在无法判断语音状态时自动停止。当前进程内服务正常运行、但遥控器
   尚未连接时显示“立即重连”；点击后只跳过当前退避等待并发起下一次连接，不重启服务，
   重复点击也不会并发建立连接。程序始终只保留一个通知区域图标：服务未启动时是
   灰色斜杠麦克风，服务运行但尚未连接小米遥控器2 Pro 时是灰色麦克风，连接后变成蓝色麦克风。
   设置窗口底部常驻说明黄色和红色仍需处理；需要操作的状态会直接写出对应按钮或动作，
   用户按提示处理到相关项目变为绿色即可。
   单击或双击通知区域图标会恢复同一个任务栏窗口。关闭窗口默认隐藏到通知区域，遥控器
   服务继续运行；需要彻底结束时，可在“设备”页底部改为“完全退出”，或从通知区域菜单
   选择“完全退出”。选项显示为“隐藏”和“完全退出”，“隐藏”仍会隐藏到通知区域；原有关闭方式选择继续保留；
3. 按一下已映射为普通动作的按键确认映射生效。管理员按键组件正常时执行保存的
   自定义映射；组件异常时全部自定义按键映射停用，只保留 Windows 原始按键操作；
4. 在“语音”页先选择语音程序。搜狗和豆包自动读取当前值；微信需主动点击刷新，打开设置并切到“语音输入”页读取“按住说话”
   快捷键；自定义程序使用无线麦上次保存的值。三种输入法和自定义程序都保留“手动录入”
   按钮兜底：手动录入后优先使用手动值，只有用户主动点击刷新图标并读取成功时，才用输入法
   当前值覆盖。搜狗录入后会同步并读回自身配置，语音助手运行时拒绝改写，需先退出；无线麦
   不改写微信和豆包的私有配置。刷新或录入成功后立即保存，并从下一次语音开始生效；录入、
   保存、正在说话或收尾时不可刷新。微信打不开、读不到、超时或中途切走时明确报错并保留原值；不会拿隐藏状态栏旧提示兜底，不自动关闭设置或切回其它窗口。
   微信和豆包会从 Windows 已安装输入法列表动态找到对应输入法，先在独立 STA 线程完成
   激活确认，再发送当前保存的按住型快捷键；超时任务会被取消，不能在本轮失败后迟到切换。
   微信还会检查系统麦克风实际使用时间；首次未确认时只重新激活并重发一次，仍未确认就释放
   快捷键、停止转发并显示“语音程序未响应，程序已禁止开麦”。当前不自动切回原输入法。
   “选择程序”行右侧的“打开设置”用于进入输入法自身设置；“管理员启动”位于程序下拉框旁。“手动录入”位于“语音按键”行最右侧，与上方操作按钮对齐；快捷键和刷新图标仍在原位。
   搜狗已安装时不显示设置
   按钮，状态文字会提示在任务栏通知区域（含隐藏图标）右键搜狗语音图标并选择
   “设置”；无线麦不会控制托盘、鼠标或设置窗口。未安装搜狗语音时，按钮显示
   “去安装”，能找到 AI 工具箱就打开并在底部
   状态栏提示用户手动安装，找不到工具箱则只给出同一提示，不自动点击下载。
   微信输入法和豆包输入法提供“打开设置”，自定义程序不显示设置按钮。只有
   实体话筒键可以选择“按住说话”，其他按键只能选择普通动作或组合键。`Alt + Space` 经 UU
   远程会打开窗口左上角
   系统菜单，不再作为建议组合；曾评估的 `Ctrl + Alt + F8` 经 UU 后按住时长不稳定，
   也没有作为默认值发包。可按宿主实际设置修改。自动读取不能证明快捷键未被其它软件抢占，
   因此搜狗、微信、豆包和自定义
   程序仍需手动确认对应按住语义本身能正常工作：
   打开记事本（或任意可编辑文本框），把光标点进文本区域，用实体键盘按下组合键，
   确认豆包语音功能出现并能输入文字。豆包的麦克风输入设备也必须选择
   `CABLE Output`（如果按上一节配置了 VB-CABLE）。手动测试通过后，光标保持在
   同一个可编辑文本框中，再按住遥控器话筒键说话、松开结束；如果手动快捷键都无法
   启动豆包，请先解决豆包快捷键或输入设备配置问题，本程序不能让本来就不工作的
   豆包输入法变得可用。微信和豆包自动读取成功后通常无需再比对；若读取失败或输入法
   更新后格式变化，按界面提示手动录入相同的按住型快捷键。
   “语音程序”是同页的可选设置：默认“不管理”，不会改变现有快捷键链路。
   选择搜狗后会自动查找已安装的搜狗语音组件；选择微信输入法后会从运行进程、
   安装记录、开始菜单和标准安装目录自动识别，新电脑正常安装后无需寻找路径，
   且由 Windows 管理，不随遥控器服务强行启动。豆包输入法会从运行进程、安装记录和
   标准安装目录自动识别，由无线麦直接适配，不归入 Windows 管理，也不作为普通程序随
   服务启动。选择“自定义程序”时可指定 `.exe` 或 `.lnk`。搜狗和自定义程序可随服务
   尝试启动，启动后只在很短时间内确认真实目标进程是否出现，不会持续轮询；查找或启动
   失败不会阻止服务。新配置
   首次选择搜狗时默认勾选“管理员启动”，自定义程序默认不勾选；两者分别记忆，用户
   手动关闭或开启后不会被切换程序、关闭设置或重新启动覆盖。旧配置原来保存的单个
   管理员选择会迁移给两种程序，不会被搜狗的新默认值覆盖。勾选时启动会出现 UAC；
   如果搜狗已经以普通权限运行，需要先退出，再让遥控器服务按保存的设置重新启动；
   搜狗或自定义程序按设置启动后，只在短截止时间内确认真实目标进程出现。每次实际
   语音按下前，搜狗最多再等待 0.6 秒确认进程；进程不存在就停止本轮，不发送快捷键或
   `MIC_OPEN`。程序不再预热搜狗语音组件，也不以可见窗口判断快捷键是否生效。
5. 需要完全结束程序时，右键通知区域图标选择“完全退出”，或从 Start Menu 选择
   “停止 无线麦”。两个入口都会先正常清理 BLE、HID、语音热键与音频资源。按键映射
   正常修改会先自动保存再退出；编辑尚未完成、自动保存失败或仍有其它未保存设置时，
   会恢复窗口，让用户选择保存并退出、不保存或取消。
   也可以从"设置 → 应用"/Start Menu 的"卸载"条目卸载（卸载会先自动停止
   正在运行的进程，再通过一次 UAC 删除预授权 HID 任务和 Program Files 中的助手，
   然后删除本程序拥有的开机启动项及安装文件；取消 UAC 时卸载会停止，避免留下失效任务）。遇到按键/语音/启动
   问题时，可以在“设备”页“诊断日志”一行点击“导出日志”，选择 ZIP 保存位置。
   默认文件名带导出日期和时间；取消保存不生成文件，没有日志时如实提示。
   关闭“诊断日志”开关后仍可导出已有日志。原始日志仍位于
   `%LOCALAPPDATA%\RemoteMic\RC003\logs`。**卸载不会自动删除设置和日志**：`config.json`、`key_bindings.json`、`logs\app.log`
   和 `logs\hid-helper.log`
   会一直保留在 `%LOCALAPPDATA%\RemoteMic\RC003` 下，因为
   安装脚本没有为这些运行期生成的文件配置卸载删除规则。如果这台
   电脑上不会再安装任何 RC003 版本（安装器或便携版）、也不需要
   保留这些设置和日志，可以在卸载完成后手动删除整个
   `%LOCALAPPDATA%\RemoteMic\RC003` 文件夹；如果还会用到
   同一台电脑上的另一个 RC003 安装，请不要删除这个共享目录。

当前源码的 HID 按键接收日志在普通 `app.log` 中保留失败分因，不要求先打开详细
诊断：包括设备宿主查询、读取权限、共享宿主保护、组件握手、控制确认、句柄关闭
和复制失败。记录只包含原因码、计数、版本/文件摘要等，不包含按键文本、设备路径
或原始异常正文。来源不确定时明确保留未知，不直接判成蓝牙不兼容或映射成功。
遇到问题请提供大致失败时间及同轮 `app.log`；需要逐次按键证据时，先开启设备页
“诊断日志”再复现，并一并提供 `diagnostic-trace.jsonl`。日志不会自动上传。

当前源码还补充元素导航记录：在服务运行、原有“诊断日志”开启时，记录切换命令实际
处理、扫描开始/完成/取消、扫描节点与可选元素数量、读取元素失败计数、方向键去向、
移动候选与未移动原因、前台切换暂停。使用同一导航实例及扫描编号关联，不把“命令
投递成功”当作扫描成功；异步事件仍需结合窗口句柄、线程与时间核对。启动/退出及
worker 异常另在普通 `app.log` 保留简要记录，覆盖服务详细日志尚未启动或已关闭时。
不导出元素名称、窗口标题、输入正文、截图或原始异常正文；仍由“导出日志”收集，
没有新增开关。2026-09-14 后续源码补齐导航按键进入监听后的分支、返回值与异常，
以及按标准控件类型汇总的扫描排除原因；关闭诊断时不进行新增前台句柄采集。
这些新增记录尚未进入现有 candidate.42 程序和 ZIP，需使用包含后续源码的版本。
详见 `CHECK-NAVIGATION-LOG-001`，不将日志增强视为导航故障已修复。

完整底层分因需要加载诊断修订 1 的 Gadget。仅更新/重启主程序不保证旧宿主中的
组件同步更新；普通日志 `hid_runtime_capabilities` 的实际
`loaded_diagnostic_revision=1`、`diagnostics_available=true` 才表示新诊断能力
可用。旧协议 4 组件仍可接收按键，但不能冒充已经获得新底层证据；重载需要安排
短暂中断，不能只为更新日志自动重启蓝牙设备。维护口径见
`MAINTENANCE.md` 的“HID 拦截失败日志补全”，加载验证见 `TESTING.md` 的
`CHECK-HID-LOG-001`。本段描述未发布源码，不表示已有公开 ZIP 包含这些记录。

通用程序诊断会记录触发前后的程序文件名、窗口/焦点和键盘布局（HKL），不保存
程序完整路径、窗口标题、输入正文或音频。现有诊断开启时附带每 250 ms 最多一次
的本机前台变化观察：语音开始后最多 30 秒，结束后另观察最多 10 秒，普通映射 2 秒；
短暂变化可能落在采样间隔内。具体 TSF 输入法仍须结合已有激活档案，不能仅凭
HKL 不变判断没有切输入法；窗口变化和原生按键调用返回都不证明气泡或上屏成功。

本机输入环境诊断还记录无线麦、当时前台程序和搜狗/微信/豆包已知进程名候选的
实际权限：是否提升、完整性级别、UIAccess、登录会话及进程创建时间。每 5 秒或
前台身份改变时重新读取，失败保持未知；进程名候选不等于已验证的语音服务身份，
权限差异也不直接等于失败原因。基本权限和剪贴板序号记录见
`CHECK-SUBMISSION-LOG-001`，已进入 candidate.38 本地测试包。

candidate.39 本地测试 ZIP 已在同一诊断开关及观察时间内补充以下证据；
candidate.38 及更早 ZIP 不含此批：

- 剪贴板归属窗口/PID/程序文件名及 Unicode 文本格式是否可用；不打开剪贴板或读取
  内容。采样中发生变化时丢弃归属；归属不保证就是写入者，也不证明文字已上屏。
- 已核对进程名的搜狗/微信/豆包窗口元数据：窗口类、显示标志、最小化、系统隐藏
  标志及宽高；每 500 ms 最多一次、每个输入法最多 8 个显示窗口，隐藏窗口按类合并
  （最多 32 类），避免后台窗口挤掉气泡。它用于对照窗口出现/消失，
  不把普通窗口当成语音气泡，不读取窗口标题或正文。
- Windows 麦克风隐私历史中的开始/结束时间；仅按已知程序文件名匹配，可能包含
  旧安装记录，不能当作当前 PID 实时开麦的证明。没有记录或查询失败仍为未知。
- 现有键盘监听中，语音开始后最多 30 秒、结束后另 10 秒内的 Ctrl+V、Ctrl+Shift+V、
  Shift+Insert 按下/松开候选，单次最多 64 条；不记录普通输入字符，不发送粘贴。
  记录不保证来自输入法；没有记录也不能排除其它文字提交方式或上游监听拦截。
- `voice_runtime_state` 记录程序判断的语音状态变化；`app.log` 记录声音通道测试
  开始、测试结果和服务停止/恢复结果，用于区分测试作用与服务重启的影响。

新增采集只服务于现有诊断时间线和显式接收采集入口，关闭诊断后停止；不改变输入法
激活、重试、按键发送、服务恢复和界面交互。查询异常隔离，仍由“导出日志”打包。
自动验证及真实宿主边界见 `CHECK-VOICE-RESPONSE-LOG-001`。

需要接收端证据时，新增内部 `--observe-shortcut` 入口可独立运行，不打开无线麦
界面或启动遥控器服务。开发示例（既有 .36 ZIP 尚不含该入口）：

```powershell
.\.venv\Scripts\python.exe -m ovb_rc003 --observe-shortcut --keys ralt+i --seconds 30 --output C:\Temp\shortcut-observation.jsonl --dry-run
```

先用 `--dry-run` 只生成采集计划；明确开始实测时删除该参数并换一个不存在的输出
文件。后续包含此入口的冻结包可将 `python -m ovb_rc003` 替换为主 EXE。
一次只允许 1–6 个指定键、1–120 秒，默认 30 秒；另记录 Shift/Ctrl/Alt/Win
修饰键，最多 2000 个键事件。只记录键码、按下/松开、系统标记和上述本机输入环境，
不记录其它普通键、标题或正文。所有事件均转交 Windows；不改配对、权限、输入法、
映射或用户配置，不向目标进程注入代码。结束卸钩；失败返回非零并保留已有证据。
输出必须是绝对路径下新的 `.jsonl` 文件，不覆盖已有文件。文件归本次诊断，
不进入 Git 或程序包，可在分析后删除。它不证明事件来自哪种远程软件，也不负责
两台电脑时钟同步；由操作者核对两端时间并对应操作。没有事件也可能是其它钩子
先处理或当前权限/桌面不可观察，不据此自动归因。

开启原有“诊断日志”后，来源验证失败、语音确认超时等已记录故障还会自动生成
`diagnostic-report.json`，保留有限的故障前后事件，最多 1 MiB 和最近 3 次故障，
服务重启后仍保留。反馈时点击“导出日志”，提供生成的 ZIP 并说明问题的大致时间。
ZIP 包含已有的 `app.log`、`hid-helper.log`、`diagnostic-trace.jsonl`、诊断报告
及主日志/诊断记录各最多 3 份轮转备份；不递归收集其它文件，不包含配置或录音。
单个文件最多取最近 8 MiB，文本截取从完整行开始；运行中的日志按文件逐个取快照，
不能保证所有文件同时截取。包内 `export-info.json` 记录版本、时间、缺失/读取失败
及截取情况；部分文件未能完整导出时会提示。压缩在后台进行，失败保留已有目标文件，
不修改原始日志、不自动上传。导出 ZIP 是用户选择保存的反馈副本，可在反馈后删除；
相关验证见 `CHECK-LOG-EXPORT-001`，本入口已进入 candidate.38 本地测试包。
关闭诊断后不继续采集，旧文件保留，可随日志手动删除。未被程序识别的异常可能
没有故障报告，因此不能只凭报告不存在判断运行正常。

本次新增底层字段还需核对 `hid_runtime_capabilities.script_matches_expected=true`；
仅诊断修订号 1 相同不足以证明脚本已更新。缺少脚本标识记为未知，不自动判为
必须重启电脑。具体故障与采集验收见 `CHECK-DIAGNOSTIC-001`。

语音日志会记录触发前后的前台进程、控件类名、焦点是否变化和文本长度是否变化，
用于辅助排查焦点或文字是否发生变化；它不能证明语音气泡已经打开，也不能代替用户确认
文字是否正确上屏。日志不读取窗口标题、输入文字或语音内容。内置“显示桌面”使用单向
最小化，不再使用重复触发会恢复窗口的 `Win+D`。

**便携版 ZIP 用户**

便携版没有停止脚本，也没有打包 Start Menu 入口或卸载程序；
下面每一步都在解压出的文件夹里手动执行：

1. 直接双击 `RemoteMicRC003.exe`（不带参数）即可打开程序窗口——这是默认
   行为；也可以在 PowerShell 里运行 `.\RemoteMicRC003.exe --settings`。在“语音”
   页点击“选推荐端点”选择 CABLE Input，再选择语音程序和语音按键；端点下拉、
   语音程序和语音按键会各自自动保存。若此时其它目录或旧版本仍在运行，按弹窗确认
   切换；更早版本需从旧版通知区域选择“完全退出”，随后当前版本会自动继续打开；
   首次打开且管理员按键组件未启用时，程序会显示“建议打开管理员按键权限”，高亮按钮为
   “打开”，旁边是文字按钮“不打开”。选择“打开”后在 Windows UAC 中选择“是”；成功后
   以后普通双击和随 Windows 启动都不再为自定义按键映射重复弹 UAC；
2. 含“选择设备”入口的版本，先按上文添加并选择遥控器。在“设备”页点击“启动服务”运行遥控器服务（使用上次已经保存的设置，不保存其它未应用
   修改）；也可以在“设备”页底部设置程序打开后自动执行一次“启动服务”，并独立设置
   “随 Windows 启动”。`.\RemoteMicRC003.exe --bridge` 启动桥接仍作为独立兼容入口保留，正常桌面
   使用不需要执行它。“遥控器服务”
   一行会显示未运行、正在启动、等待小米遥控器2 Pro、小米遥控器2 Pro 已连接或启动失败等真实阶段；
   只有桥接运行状态确认设备连接后，界面才显示“小米遥控器2 Pro 已连接”。
   Windows 右下角通知区域图标和窗口属于同一个程序；服务未启动、等待小米遥控器2 Pro、已经
   连接分别显示灰色斜杠麦克风、灰色麦克风和蓝色麦克风。关闭窗口默认隐藏到通知区域，
   遥控器服务继续运行；需要彻底结束时，可在“设备”页改为“完全退出”；
3. 按一下已映射为普通动作的按键确认映射生效。预授权 HID 助手可用时，普通权限
   便携版会执行保存的全部自定义按键映射；助手未启用或异常时，全部自定义按键映射
   停用，只保留 Windows 原始按键操作；
4. 手动确认豆包输入法语音快捷键的步骤和上面"安装器用户"一节完全相同（打开
   记事本、光标点进可编辑文本框、按下已配置的组合键、确认豆包能输入文字、
   确认豆包麦克风输入选择的是 `CABLE Output`），这里不重复；
5. **停止**：右键 Windows 右下角通知区域的无线麦图标，选择
   “完全退出”。该入口会先正常清理 BLE、HID、语音热键与音频资源再结束
   进程；只有托盘不可用且程序无法正常退出时，才使用任务管理器结束
   `RemoteMicRC003.exe`；
   **卸载/移除**：如果这台电脑以后不再使用任何无线麦版本，先在“设备”页
   “按键接收”一行点击“移除权限”并确认一次 UAC，再删除整个解压文件夹。该操作会
   移除当前 Windows 账号下所有无线麦版本共用的管理员按键组件；其它安装版或便携版
   以后再次使用自定义按键映射时，需要重新启用并再次确认 UAC。直接删除解压文件夹只会
   移除程序本体，不会自动删除已授权助手。但便携版运行时同样会把 `config.json`、
   `key_bindings.json`、`logs\app.log` 和 `logs\hid-helper.log` 写到
   `%LOCALAPPDATA%\RemoteMic\RC003`（和安装器用的是同一个
   目录）——删除解压文件夹**不会**清除这些设置和日志文件。如果这台
   电脑上不会再用到任何 RC003 安装（便携版或安装器）、也不需要保留
   这些设置和日志，可以额外手动删除整个
   `%LOCALAPPDATA%\RemoteMic\RC003` 文件夹；如果还会用到
   同一台电脑上的另一个 RC003 安装，请不要删除这个共享目录。

### 默认按键映射与特殊行为

RC003 共 **13 个可映射物理按键**。麦克风图标键默认承担“按住说话”，也可以
改为普通动作；其他按键不能传送遥控器声音，只能选择普通动作或组合键。双击和
长按不允许语音动作。旧开关型、非话筒键语音或次级手势语音配置升级后会整键
停用，必须重新选择；编辑完成后会自动保存，程序不会把它们悄悄转换成按住说话。遥控器**没有独立
的物理静音键**（“系统静音”只是可选的手动绑定，不是任何按键的默认映射）；
“返回”默认映射为退格动作。“TV”默认映射为“应用切换”，使用 `Ctrl+Alt+Tab`
打开并保留 Windows 任务切换器；随后可用方向键选择，按确定键进入，不需要持续按住
Alt。设置页的“检测真实按键”同时使用 Raw Input 与可选 HID tap；后者补齐 Windows
普通输入链路丢失的返回和音量键。

方向、退格、音量和滚轮动作可以在持续按住时连续执行；滚轮仍只会在方向、返回、
音量加减这些原本允许连发的实体键上连发。自定义组合键始终按“一次实体
按下对应一次完整点按”处理，不再定时重复组合键，以降低修饰键未释放和意外连发
风险。为普通话筒键配置的双击/长按仍按普通手势处理。

动作下拉按“按键操作、鼠标与导航、系统与媒体、启动应用、其他”分组显示，分组标题
只用于阅读，不占用选项索引。鼠标与导航组提供左键、右键、中键、X1、X2 单击，以及
滚轮向上、向下；这些动作操作当前鼠标位置，不移动指针，也不包含拖拽、仅按下、仅
松开、横向滚动或一键双击。任意单击、双击或长按都可以选择这些动作。
“元素导航开关”也可用于上述三类入口：首次触发扫描当前前台窗口，再次触发退出当前
导航。导航运行时仍使用桌面
主进程内独立的 Qt/UI Automation 运行对象，不会再启动长期伴随进程；已映射为方向、
回车、右键菜单和音量的遥控器按键分别用于移动、点击、右键和滚动。旧的
`--element-navigation` 只保留兼容入口。真实宿主软件和实体遥控器仍按 `TESTING.md`
人工验证。

每个“录入”弹窗都可在“按键录入”和“手动输入”之间切换。像 `Win+L` 这种一按就会
触发系统动作的快捷键，应切到“手动输入”后填写；也支持
`Lctrl+Win+左箭头`、`Lctrl+Win+右箭头` 和常用中文按键名，保存时仍写入兼容的英文
按键标记。单独填写 `Win` 会按左 Win 键处理。`Ctrl+Alt+Delete` 属于 Windows 安全按键，
不能由普通程序模拟，因此会直接拒绝保存。映射执行时，`Win+L` 使用 Windows 专用锁屏
接口；其它 Win 组合继续使用现有按键发送与失败补松链路。

鼠标单击的按下和抬起会在同一次 `SendInput` 中成对提交。若系统只接收了按下，程序会
立即单独补发抬起；补发仍不能确认时会保留具体鼠标键的欠松开状态，并在下一动作、
重连清理和完全退出前重试，完成前不再注入新动作。键盘动作沿用同一所有权原则。
新映射自动保存时，已经开始的单击、双击、长按或连发会继续使用保存前的动作，
整次手势结束后才切换。主映射发现实体鼠标正在按住同名键时会跳过合成点击；元素导航
需要移动指针时，只要任一实体鼠标键仍按住，就不会移动或点击，避免打断正在进行的拖拽。
元素导航自己的点击补松若仍未确认，也会阻止后续鼠标动作，并在退出前再次尝试释放。
旧版程序不认识新增鼠标动作，降级运行前应先把对应映射改回旧版支持的动作。

普通动作输入框也可以直接填写 Quicker 的
`quicker:runaction:动作ID或名称?参数`。程序只接受这一种 Quicker 动作协议，不会
把任意 URI 或命令交给 shell；触发后由 Windows 交给已安装的 Quicker 处理。Quicker
需要正常注册该协议，且按其[外部启动说明](https://getquicker.net/kc/manual/doc/quicker-starter)
不应以管理员身份运行。普通权限桥接和管理员桥接下的实际触发仍要分别真机验证。
后续对接边界、实现入口、悬浮动作导航和待实测项统一维护在
[Quicker 对接专项资料](discussions/quicker-integration.md)。

`Chromecast Remote` 当前只完成了仓库外的独立按键底层验证，尚未进入本程序的支持
范围。已核实的按键协议、免 BTVS 来源确认、实测结果、正式接入边界和语音验证顺序
统一维护在
[Chromecast Remote 接入专项资料](discussions/chromecast-remote-integration.md)。

### 隐私与来源、真机验证事项

不持久化保存真实蓝牙地址、HID 路径或设备令牌；本候选源自同一 GPL-3.0
参考项目的 Windows 实现，并在本仓库中完成了品牌、构建和说明适配。历史候选
曾记录“已通过真实硬件验收”，包括配对、逐键和豆包语音；但 2026-08-20
重新复核后陆续发现 WDM-KS 无声、设置页漏键、切换竞态和运行中语音设置未应用。
后续实测已经证明多候选连接、逐键识别、有效语音 PCM、可见识别文字和 F5 防漏，
遥控器点按持续传声的最后一条协议探针随后也未收到启动信号，因此当前产品只保留
实体话筒键按住说话。微信输入法 `2.1.3.18` 的本机核实、2026-09-08 用户日志和
[`ATTRIBUTION.md`](ATTRIBUTION.md) 已登记的 GPL Windows 参考实现共同表明：旧实现实际向
`wetype.statusbar.window` 的固定坐标投递鼠标消息，状态栏在远程窗口隐藏时程序会自行
禁止开麦；这不是微信底层语音接口。2026-09-12 已确认隐藏状态栏提示会保留旧快捷键，当前停止使用该来源，改为主动刷新时打开微信设置读取
“语音输入”页的“按住说话”值，连续两次一致才接受；自动切页只向已核验的微信原生视图投递导航点击，不移动系统鼠标、不发快捷键，不修改微信设置。读取或保存失败保留原值与来源。运行时先在独立 STA 激活 WeType，
冷切换等待 50 毫秒，再逐边沿发送无线麦当前保存的组合键，边沿间隔 80 毫秒；不再点击
状态栏或把气泡可见当作成功。按键发出后还会读取系统麦克风使用记录，确认微信确实开麦；
首次未确认时只恢复重试一次，仍失败就释放按键并停止转发。
豆包输入法会读取用户配置中的 `voice.voiceLongPressShortcut`，并通过独立输入法适配
激活豆包后发送同一按住型快捷键。搜狗和自定义程序继续使用各自路径，当前不自动切回
原输入法。
历史记录
不能替代当前构建的验收；详见
`MAINTENANCE.md` 与 `TESTING.md`。只有用户明确确认后，桌面程序才会通过 Windows 的
`runas`/UAC 启动 VB-Audio 官方安装器；桌面主程序本身不会提升权限。HID 注入由安装时
单独授权、位于 Program Files 的窄职责助手执行，不把设置、BLE、音频或用户配置带入
管理员进程。
用户还可以在“语音”页明确选择让 Windows 以管理员权限启动搜狗或自定义第三方
语音程序；微信输入法由 Windows 管理，不提供该选项。该操作不会提升
无线麦自身，也不会把第三方程序打包进本项目。

## 功能实现

Windows 客户端围绕 RC003 使用场景实现，主要功能如下：

- 使用 **WinRT BLE** 查找已配对的 RC003，并按设备名称精确匹配；找到 0 个或多个候选时都会拒绝猜测。服务与特征读取使用 `BluetoothCacheMode.UNCACHED`，避免 Windows 返回过期枚举。
- 使用 Windows **Raw Input** 接收遥控器普通按键，并校验选中的 HID 路径，避免误接收另一只相同型号设备的事件。
- 对 Windows Raw Input 丢失或到达过晚的 HID usages，使用本项目维护的 Frida Gadget WUDFHost tap。该 tap 上报遥控器的**全部键盘 usage**（返回 `0xF1`、音量 `0x80/0x81`、方向/OK/Home/Menu/TV/Power 等）。当前协议先核验所选实体的设备来源（独占宿主保留严格复核的兼容路径），在 Windows 复制报告之前保存原值并清空 usage；复制成功后 Python 才处理原报告，避免原生键与映射双重执行，具体边界见下方“运行架构”。安装版和便携版首次启用时通过一次 UAC 登记固定的按需任务，普通权限主程序只启动该任务；Windows 回读任务时允许补出一个直属、无属性、无内容的空 `Triggers` 容器，但任何真实触发器、自动维护或失败重启设置都会被拒绝。管理员助手从正式配置入口只读所选设备摘要，自行重新定位并核验 RC003 的 `WUDFHost.exe`；不接收调用方传入的 PID、程序路径或配置路径，不执行其它用户设置。助手异常时全部自定义按键映射停用，遥控器只保留 Windows 原始按键操作；运行中失联会先补齐已认领按键的松键。
- 连接 ATVV GATT 服务，协商能力，接收并解码 16 kHz IMA/DVI ADPCM 语音帧。
- 使用 **PortAudio** 把解码后的语音写入用户明确选择的输出端点（WASAPI 优先、DirectSound 回退，拒绝阻塞 API 不支持的 WDM-KS；按端点能力输出立体声并复制声道；16 kHz → 48 kHz 有状态连续插值；解码后经 20 Hz 高通 DC 阻挡和 +10 dB 增益）。阻塞式播放写入在 64 帧有界 worker 中串行执行，BLE 回调只快速入队；停止屏障保证尾部 PCM 先于宿主收尾，队列满或写失败会停止转发并请求重连。语音页选择或检测端点时会真实预检并独立保存，不会自动使用 Windows 默认设备。
- 语音入口按目标程序分开处理：微信和豆包输入法分别在独立 STA 线程中动态查找并激活本机安装的对应输入法，再以单次 `SendInput` 逐边沿发送无线麦当前保存的按住型快捷键，松手时反向释放本次实际按下的同一组键。STA 超时会取消该次操作，避免失败后迟到切换。微信冷切换等待 50 毫秒，边沿间隔 80 毫秒，并通过麦克风 `LastUsedTimeStart` 确认确实开麦；未确认时只恢复重试一次，仍失败就释放按键并禁止继续转发。搜狗会读取自身当前值，录入后先同步并读回；微信只在主动刷新时打开真实设置页读取当前值，豆包从用户配置读取 `voice.voiceLongPressShortcut`。三种输入法均保留手动录入，手动值优先，主动刷新成功才覆盖。自定义程序保存无线麦本地记忆。UU 远程的按住边沿仍按 `TESTING.md` 做真机验收。
- “语音程序”是独立的可选管理层，默认关闭。当前内置搜狗语音组件、微信输入法和豆包输入法，并支持用户指定其它 `.exe`/`.lnk`。搜狗快捷键通过其自身落盘配置读取和原子改写，运行中拒绝改写；已安装时界面只提示用户从通知区域右键搜狗语音图标进入设置，不控制托盘、鼠标或设置窗口，未安装时“去安装”可转到 AI 工具箱并提示手动安装。微信输入法由 Windows 管理；豆包由无线麦直接适配，不归 Windows 管理，也不作为普通程序随服务启动。搜狗和自定义程序可随遥控器服务尝试启动，启动后只做有截止时间的进程确认，不持续轮询。语音按键的手动值保留外框，自动值和默认值无框；录入及手动保存过程中也显示外框，取消或失败后恢复原来源对应的外观。搜狗、微信和豆包的刷新图标固定在框外右侧，该行最右侧为“手动录入”按钮；有框也仍需点击该按钮才能修改。主动刷新读取并保存成功后才切为自动来源并去框，读到同一快捷键也会切换；刷新失败时保留手动值和外框，切换页面或重新打开程序也保留已保存来源；读取成功后立即保存，录入、保存、说话和收尾时不可刷新。当前配置 schema 13 记录每个语音程序的快捷键来源为默认、自动读取或手动录入；合法手动值保持最高优先级，空手动值会降为待自动读取或手动录入的默认状态。新配置的搜狗默认开启管理员启动、自定义程序默认关闭，旧的共享选择原样迁移，用户后续选择永久记忆。管理员启动通过 Windows UAC；程序缺失、UAC 取消或启动失败都不会阻止服务。
- 提供 RC003 的 13 键单键映射界面。单击、双击和长按动作可使用内置键盘动作、鼠标单击/滚轮、电脑快捷键或 `quicker:runaction:` URI。只有实体话筒键可选择“按住说话”，它也可以改为普通动作；其他实体键只提供普通动作。遥控器两个实体键的组合识别已停用；HID tap 可用时由 Gadget 在设备栈内认领原报告后执行所选动作，不可用时全部自定义按键映射停用，只保留 Windows 原始按键操作。
- 提供“设备”“按键”“语音”三个页面。设备与权限检查结果放回对应业务行，仍区分自动检查和“需要手动验证”，不会把进程存活伪装成硬件验收通过；黄色或红色状态直接写出对应按钮或操作，窗口底部常驻提醒用户处理到相关状态变为绿色；随 Windows 启动、程序启动时自动执行一次“启动服务”和关闭窗口行为作为一整组放在设备页底部。
- 桌面程序使用 PySide6 Essentials + Qt Quick/QML；便携版和安装器都通过 PyInstaller 打包，不要求终端用户另装 Python 或 Qt。成品根目录只保留用户入口 `RemoteMicRC003.exe`：双击（无参数）或 `--settings` 打开同一个桌面程序，登录自启使用隐藏参数 `--background`，`--bridge` 只保留为兼容启动形式，仍会进入同一个桌面主进程并请求启动进程内桥接 worker。窄职责 `RemoteMicRC003HidHelper.exe` 收在 `_internal` 内，只供安装器、“修复权限”和固定计划任务调用，不是第二套主程序，也不需要用户手动打开。同一 Windows 登录会话只保留一个长期主进程；再次启动只恢复已有窗口，兼容 `--bridge` 则只通知已有进程启动服务。
- Qt 桌面主进程统一持有窗口、通知区域图标、桥接 worker 和元素导航。图标按服务未启动、等待小米遥控器2 Pro、小米遥控器2 Pro 已连接显示灰色斜杠麦克风、灰色麦克风和蓝色麦克风。关闭窗口默认先结束按键录入或检测，再隐藏到通知区域并继续后台运行；用户主动选择“完全退出”时才停止全部长期资源。隐藏或退出清理失败都会恢复窗口并提示。
- 安装器和 Start Menu“停止”入口通过一次性 `application-exit-request.json` 请求同一个主进程完整退出，并等待进程互斥真正释放。退出请求一旦进入处理，新的桥接启动、自动恢复和手动重启都会停止排队；用户取消未保存提示后才恢复正常操作。当前版本拒绝退出或超时时，安装和卸载都会停止，不会用强杀绕过清理失败。
- 配置写入采用临时文件 + fsync + `os.replace` 原子替换，失败不会留下半写的 JSON；桥接 worker 在下一次按键或语音事件前按 mtime 一起热加载按键映射和按住说话设置，活跃会话会在收尾后再切换，磁盘数据损坏时保留最后一份有效设置。连接设备和音频输出端点仍需重启桥接。
- VB-CABLE 只是可选的语音路由方案。只有用户明确点击并确认 UAC 后，才会通过 `runas` 启动 VB-Audio 官方安装器；桌面主程序不会提升自身权限，也不会修改系统默认输入/输出设备。

## 运行架构

源码入口位于 `apps/windows/rc003/src/ovb_rc003`，内部 Python 包名仍保留
`ovb_rc003`，以保持现有导入、启动与构建入口兼容；用户可见名称统一为
“无线麦”，内部可执行文件名、安装器文件名和配置路径继续保持兼容。

运行流程大致如下：

1. “语音”页的输出端点和语音程序自动保存；搜狗和豆包自动读取自身快捷键，微信由用户主动刷新打开设置读取，三者均保留手动录入兜底，手动值只有主动刷新成功才会覆盖。微信和豆包运行时先激活对应输入法，再逐边沿发送当前保存的组合键，松手释放同一会话实际按下的键，当前不自动切回原输入法。需要快捷键的其它程序会按各自支持范围校验，不合规时保留原值并说明原因。“选择程序”状态只说明软件安装或进程状态；“试输入”只打开普通文本框，是否成功以实际进入的文字为准；设备、服务、运行状态与识别结果不再混入该入口。输出端点选择会执行 open/start/stop/close 预检，再以原子写 + 回读校验落盘并自动刷新诊断；只有当前未使用推荐端点时才显示“选推荐端点”，不再存在第二次“应用”。“按键”页的单击、双击和长按映射在编辑弹窗点“完成”后自动保存，恢复内置默认确认后也立即保存；落盘前仍会校验电脑组合键、Quicker URI、只有实体话筒键可传声的边界和次级动作边界。桥接 worker 在下一次输入事件前热加载映射和语音设置；输出端点变更仍在重启后用于实际音频连接。
2. Qt 桌面主进程持有唯一窗口、通知区域图标和进程内桥接 worker；“设备”页启动或
   “启动程序时运行遥控器服务”只启动该 worker，不创建第二个长期进程。应用级互斥
   阻止重复主程序，桥接资源互斥同时阻止升级期间的旧独立桥接抢占 BLE、Raw Input、
   HID 或音频；能识别的旧桥接会先走正常退出再迁移，无法安全控制的更老实例会明确
   提示用户手动退出。完全退出使用同一套 BLE、HID、热键与音频清理流程。服务/特征读取
   使用 `BluetoothCacheMode.UNCACHED`，避免陈旧缓存。
3. RC003 HID tap 在核验为遥控器独占的 WUDFHost 内接收全部键盘 usage。协议 4 在 Windows 复制报告之前保存原报告并清空 usage，复制成功后才把原始边沿送入映射层；不再依赖下游全局方向钩子抢先吞原键。共享宿主或来源无法核实时拒绝接管；tap 失败时不由 Raw Input 补发自定义映射，失联时先清理已认领的按键。管理员助手负责受限的宿主接入，不安装新键盘驱动、不修改 Windows 蓝牙配置。该路径依赖 Windows 内部实现，本机实测通过不代表所有 Windows 和蓝牙组合均已兼容。具体协议及失败恢复见 `WINDOWS-ARCHITECTURE-LEDGER.md` 的 8.2 节，验收见 `TESTING.md` 的 `CHECK-HID-COPY-001`。实体话筒键按住说话同时驱动宿主快捷键和 ATVV 音频，其他按键只进入普通动作分发。
4. 元素导航运行对象在 Qt 桌面主进程启动时创建；按键回调提交开关、目标窗口或导航动作，实际
   UI Automation 扫描、覆盖框和点击回到 Qt 事件循环执行。完全退出会同步关闭该运行
   对象。旧 `--element-navigation` 和 Win32 命令窗口只作升级兼容，不是正常产品的长期
   伴随进程。导航源码仍可由相邻的 `../orthofocus` 模板导出为独立项目；无线麦与独立版
   继续共用 `scripts` 中同一份算法源码。
5. BLE 断开、Raw Input 路径失效、热键发送失败或音频写入失败时，相关资源会先关闭，再按策略重连；不会继续向失效音频端点写入数据。

设备发现、音频端点和语音热键均采用“明确选择、失败即停止”的策略。程序不保存真实
蓝牙地址、HID 路径或设备令牌，也不会为了让界面显示“已连接”而猜测设备状态。
`config.json` 的 `remote_selection` 仅保存 Windows ContainerId 的 SHA-256 摘要、
支持的型号档案和当前选择；不保存原始 ContainerId。它用于本机识别同一设备，
移除记录即清除该软件记忆；重新配对造成身份变化时需重新添加。

### 按键采集、回放与动作适配

不要直接修改 `raw_input_windows.py` 里的扫描码来猜测返回键或音量键。先用被动采集
工具确认 Windows 实际交付的是键盘事件还是 HID report，再把稳定的物理签名绑定到
RC003 的逻辑键。这是开发诊断入口，不是日常配置的必需步骤；采集程序不执行映射，
但不能保证 Windows 原生按键不会作用于前台，应先选择无敏感操作的测试窗口。

在本目录的 PowerShell 中运行：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
.\.venv\Scripts\python.exe src\rc003_key_test.py guided --duration 20
```

更推荐使用按键向导：它会依次提示返回、音量+、音量-，每个键完整按下并释放后
自动进入下一个键，不显示鼠标或其他设备的 Raw Input，也不主动注入音量或删除动作。
如果需要逐个手动运行，也可以使用：

```powershell
.\.venv\Scripts\python.exe src\rc003_key_test.py capture --assign back
.\.venv\Scripts\python.exe src\rc003_key_test.py capture --assign volume_up
.\.venv\Scripts\python.exe src\rc003_key_test.py capture --assign volume_down
```

每次命令只测试一个键：按一下目标键并完整释放。工具会在
`%LOCALAPPDATA%\RemoteMic\RC003\captures` 保存 JSONL 原始样本；只有同时采集到按下、释放
且没有解码错误时，才会把物理签名写入 `key_bindings.json` 的 `physical_bindings`。失败或
超时不会污染已有绑定，也不会写入 HID 路径或蓝牙地址。绑定完成后重启桥接，再用下面的
命令离线确认样本仍然同时包含按下和释放：

```powershell
.\.venv\Scripts\python.exe src\rc003_key_test.py replay `
  --input "$env:LOCALAPPDATA\RemoteMic\RC003\captures\<capture>.jsonl" `
  --button back
```

如果尚未安装可选 Frida Gadget，或 tap 日志显示没有找到 RC003 WUDFHost，普通采集工具
在按键时仍然完全没有事件，再运行广域 Raw Input 探针。它只记录
完整的 `WM_INPUT`，不会执行映射或注入按键；`--seconds` 到期后会自动退出：

```powershell
.\.venv\Scripts\python.exe src\rc003_broad_raw_probe.py `
  --seconds 30 `
  --output "$env:LOCALAPPDATA\RemoteMic\RC003\logs\broad-raw-probe.jsonl"
```

看到 `RC003 HID report tap state: ready` 后，依次只按一个目标键并完整释放。若日志有 `raw_input`，先保留
其中的 `raw_type`、`body`、键盘字段和 `path` 交给解码适配；不要把 `path` 或蓝牙
地址复制进 `key_bindings.json`。若连广域探针也没有 `raw_input`，但 tap 已显示 ready
后仍没有 `RC003 direct HID usage down`，问题在配对设备的 HidOverGatt 注入/报告链路，
而不是按键动作映射。

回放通过仅能证明该份样本可解码，不能排除实时重复、接管失败或按键发送问题。
还需核对实时链路日志和该逻辑键的动作配置。语音键不能通过普通 `physical_bindings`
绕过实体话筒键的传声边界，必须单独
验收：先手动确认所选输入法配置的**按住型语音快捷键**在文本框中可启动，再按遥控器
语音键，同时检查 ATVV 音频、输出端点和日志中的 voice lifecycle。

公开边界检查会阻止源码、日志、测试输出或未审查的本地路径进入公开发布范围：

```powershell
.\build\check-public-boundary.ps1
```

如果同一状态的 `build-candidate.ps1` 已成功，该项结果直接复用。

Windows GitHub Actions 工作流位于 `.github/workflows/windows-rc003-ci.yml`。运行结果
可在 <https://github.com/ZSTDJan/windows-remote-mic-app/actions> 查看。CI 没有真实 RC003 硬件，
因此构建和测试通过也不能替代真机配对、按键和语音链路验收。

## 已知限制

- 豆包在本地输入框能唤起语音，但在远程控制窗口可能不出气泡，当前作为已知兼容
  限制保留。已核实本机 `0.9.0.0` 存在输入法激活、输入连接、前台/输入焦点进程
  匹配和快捷键冲突检查；现有测试日志尚未确认失败当时命中了哪项。暂不强制绕过
  豆包检查、不修改其全局语音设置，也不把本地成功当作远程支持。本轮没有增加
  豆包内部启动条件采集；后续恢复排查时再补针对性证据。
- 微信在远程窗口可出现语音气泡，但识别结果可能仍需手动粘贴；本轮没有修复
  远程自动上屏。元素导航已修复自身窗口的映射/Qt 接收路径，仍待包含修复的开发版
  人工验收；本机微信可见内容尚未提供可导航控件，空扫描仍未修复。当前进展及复测
  入口见 `TESTING.md` 的 `CHECK-NAVIGATION-LOG-001`。

- 当前版本未签名，首次运行可能触发 SmartScreen 提示，属预期行为。
- 完整冻结包包含经过固定哈希校验的 Frida Gadget 和独立 HID 助手；安装版或便携版
  首次启用自定义按键映射时确认一次 UAC，升级、修复或卸载该管理员组件时会再次确认。日常启动、桥接和登录自启
  不弹 UAC。如果升级时仍在运行的旧程序本身是管理员进程，安装器还可能先请求一次
  UAC 用于核实并关闭它；取消后不会覆盖旧程序。源码调试仍需从管理员终端启动；只有
  日志出现 tap ready 和真实按键边沿，才能确认 HID 旁路可用。
- 预授权 HID 任务当前只支持“正在登录的账号本身属于管理员组”的 Windows 场景；标准
  账号通过 UAC 输入另一管理员账号凭据时，任务无法作为当前标准账号的无提示提权入口。
- VB-CABLE 是可选的语音路由方案；未安装时语音默认没有虚拟麦克风路由，需要
  用户自行配置输出端点。当前播放实现不支持 `Windows WDM-KS`，应使用
  `Windows WASAPI`，必要时回退 `Windows DirectSound`。
- 遥控器没有独立的物理静音键；语音键的 F5 兼容事件只用于识别，不再作为普通 F5 注入到主机。
- Windows 没有一个可供本程序可靠读取的统一权限状态 API；相关入口和手动检查放在
  对应设备或语音行中，不会显示虚假的“已授权”。
- DJI Mic 2 不再提供设备选择或自动诊断入口；底层设备档案和端点识别仅保留作旧配置
  兼容，不属于本候选承诺的用户功能。
- ATVV 语音延迟与音量、长期重连稳定性仍建议在更多真实场景中继续观察。
