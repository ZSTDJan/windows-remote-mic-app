## 当前维护批次

### 2026-08-20 RC003 基础功能修复

状态：检查点待实测，自动验证与真机验收分开记录。

用户可见问题：

1. 设置页的“检测真实按键”只能识别 Windows Raw Input 暴露的按键，
   返回键和音量键等由 Windows 键盘栈丢弃的 usage 无法在该入口出现。
2. 遥控器可以唤起和结束宿主语音输入，但讲话没有声音进入识别程序。
3. 桥接已经运行时再次点击“保存并启动桥接”，重复子进程弹出系统模态框，
   同时设置页误显示该重复子进程“目前仍在运行”。
4. 关闭设置窗口后桥接仍在后台运行，但没有通知区域图标或菜单，用户无法
   直观看到桥接仍在运行，便携版只能通过任务管理器退出。
5. “按住说话”已能产生识别文字，但“按一下切换”仍在第一次短按松开时
   立即结束 RC003 音频，无法在两次短按之间持续讲话。
6. 后台桥接运行时，从通知区域打开的第二个设置进程无法使用“检测真实
   按键”；普通映射在记事本中仍能执行。
7. 异机删除并重新配对后，Windows 设置只显示一个 RC003，但 WinRT 仍返回
   两个名称匹配候选，桥接在连接前失败关闭。
8. `fix6` 已能连接并在长按时识别语音，但切换模式同一次实体按下被
   `AudioStarted`、legacy F5、HID 和 ATVV mic 多次报告，刚开启就被误判为
   第二次点击并关闭。
9. `fix7` 首轮多来源合并生效，但 `AudioStopped` 早于排队中的 F5/HID
   释放；同步低层 F5 回调还会等待 PortAudio 初始化约 1.5 秒，切换模式因而
   时灵时不灵，记事本偶发收到原生 F5 并插入日期时间。
10. `fix8` 已能稳定得到识别文字且未再泄漏日期时间，但用户在设置页切换
    HOLD/TOGGLE 和快捷键后，运行中桥的行为没有变化；日志仍显示旧 TOGGLE
    状态机。
11. `fix11` 中切换模式第一次短按后仍无声，必须先长按才能得到识别；日志
    显示续发 `MIC_OPEN` 时实体 F5 尚未 up。
12. 短语音会话存在开始/停止控制完整但 `frames=0 samples=0`；独立
    VB-CABLE 合成信号验证不能解释所有空会话。
13. 多轮 Windows TOGGLE 时序修复后，主动续开仍只有开始控制事件、没有持续
    PCM；需要区分客户端缺陷与 RC003 固件不产音频。

已确认原因：

- `BUG-001`：配置保存了 `Windows WDM-KS` 播放端点；当前 PortAudio
  阻塞式输出流不支持该 host API，流在收到 PCM 前即打开失败。
- `BUG-002`：设置页只启动 Raw Input；Frida HID tap 的启动函数只证明
  后台线程已创建，注入、连接、心跳和真实 HID IO 状态没有进入应用日志。
- `BUG-003`：重复桥接子进程先显示模态提示再退出；设置页只轮询 1.5 秒，
  因提示框仍在等待用户点击而把该子进程误判为成功启动。
- `BUG-004`：设置进程与桥接进程有意分离，但后台桥接没有 Windows 通知
  区域生命周期入口；关闭设置窗口不是停止桥接操作。
- `BUG-005`：旧切换状态机把第一次物理松开产生的 `AudioStopped` 当成宿主
  第二次切换，同时关闭逻辑会话；短按 PCM 只有 60 至 195 毫秒。
- `BUG-006`：后台桥接已经独占 HID tap 端口并吞掉原始键，托盘打开的设置
  进程再次启动 Raw Input/HID tap，必然与资源所有者冲突或看不到事件。
- `BUG-007`：异机计数确认两个 RC003 使用不同设备 ID；PnP 检查确认可见的
  `MI RC` 与隐藏中文名节点属于不同容器。精确删除隐藏节点后，Windows 扫描
  会从配对数据库重建它。修复改为多候选时探测 UNCACHED ATVV 服务，只
  选择唯一可用候选；两个都可用时仍失败关闭。
- `BUG-008`：同一实体麦克风按下通过四条异步路径到达；旧的 Raw Input 和
  AudioStarted 局部门闩在第一个重复来源后即被清除，后续来源将切换状态
  再改变一次并发送 `MIC_CLOSE`。
- `BUG-009`：音频停止不是单独可靠的物理手势结束边界；低层键盘钩子线程
  也不能同步进入可能打开 PortAudio 的应用状态机。重复音频通知进一步放大
  了开关竞态。
- `BUG-010`：设置窗口正确写入 `config.json`，运行中桥却只按 mtime 热加载
  `key_bindings.json`；语音生命周期和快捷键只在进程启动时读取。
- `BUG-011`：按键检测请求可能先被 `AudioStarted` 或 ATVV mic 抢跑，后到
  F5/HID 虽能让界面显示 `mic`，正式语音状态却已经被改变。
- `BUG-012`：TOGGLE 在 `AudioStopped` 时立即续开，但真机实体 F5 约 108
  毫秒后才 up；设备回复续流开始却不发送 PCM。
- `BUG-013`：一次性检测的并发来源先读取请求再争锁；Windows 共享冲突可让
  锁胜者和败者同时失败，设置页得不到结果。
- `BUG-016`：CONTROL/AUDIO 分队列且控制优先，`AUDIO_STOP` 会越过已入队
  音频并先关闭 decoder；并发 WinRT 回调还要求序号分配和入队原子化。
- `BUG-017`：RC003 正式产品路径是 HOLD；主动 `MIC_OPEN` 可返回开始控制
  但不发送音频。TOGGLE 只剩实体 `START_SEARCH -> MIC_OPEN` 的 On-request
  窄路径尚未真机排除。

本批次范围：

- 只修复 RC003 的音频路由、语音触发配置独立性、HID tap 状态与设置页

实施结果：

- 音频端点现在明确拒绝 `Windows WDM-KS`，同名端点优先使用
  `Windows WASAPI`，其次使用 `Windows DirectSound`，保存前执行真实
  `open/start/stop/close` 预检。
- 语音生命周期与宿主快捷键已分开保存，“按住说话/按一下切换”不再覆盖
  用户录制的快捷键。
- HID tap 改为隐藏独立子进程，保留目标 PID、WUDFHost 名称和固定 Gadget
  哈希校验，并把启动到有效 HID IO 的状态写入 `app.log`。
- 管理员现场诊断确认 WUDFHost 进程名查询必须发生在
  `SeDebugPrivilege` 启用之后；注入器现已按此顺序执行。同一宿主 PID
  注入失败后保持稳定失败状态，只在 PID 改变后重试。
- 设置页的按键检测同时监听 Raw Input 与 HID tap；任一路径捕获后都会统一
  停止监听，检测期间不会执行已配置动作。
- 设置页发起的桥接子进程使用隐藏来源标记；重复实例立即以退出码 3 返回，
  不再被模态提示框阻塞并误判为启动成功。
- 已保存 WDM-KS 配置且检测到标准 CABLE Input 时，设置页预选 WASAPI
  视图，等待用户保存并通过真实预检后才持久化。
- 后台桥接新增原生 Windows 通知区域图标；双击打开设置，右键可打开设置
  或正常退出。退出请求取消 asyncio 运行任务，并继续使用原有 BLE、HID、
  语音热键、音频和互斥锁清理路径。
- 切换语音改为真正的第一次按下开启、第二次按下关闭；第一次物理松开后
  续发 `MIC_OPEN`，第二次按下发送线程安全 `MIC_CLOSE`，并用 close-pending
  门闩隔离关麦竞态。按住模式保持不变。
- 设置页在后台桥接运行时改走一次性本地文件 IPC；后台捕获下一键、回传
  逻辑 `button_id` 并吞掉该次 down/up，不执行映射。没有后台桥接时仍走
  原本的本地 Raw Input + HID tap。
- 麦克风触发增加跨来源手势门闩；首个 HID、legacy F5、ATVV mic 或
  `AudioStarted` 判定一次切换，后到来源只并入同一手势，`AudioStopped`
  后下一轮按键才可再次改变状态。
- 手势门闩增加音频停止与全部物理 up 的双边界；重复音频 start/stop 去重；
  低层 F5 回调改为事件循环异步投递，并用连接 generation 丢弃清理前排队
  的旧事件。切换关闭不再重新打开播放端点。
- 桥接同时监控 `config.json` 和 `key_bindings.json`。新语音生命周期与快捷键
  在空闲时立即热应用，活跃会话则暂存到完整收尾后应用；BLE-only
  `AudioStarted` 路径也会刷新设置。日志记录实际生效的模式与快捷键。
- 同轮完整代码审查修复了三个确定性问题：PortAudio `close()` 失败时保留
  资源句柄以便重试；隐私禁用字段按大小写不敏感校验；开始菜单环境变量缺失
  时不再误扫当前工作目录。
- 麦克风按键检测改用独立跨来源门闩，检测期间不会改变正式语音状态。
- TOGGLE 续开改为待全部实体来源 up 后执行；BLE-only 使用 200 毫秒有界
  宽限，第二次关闭、清理和重连均取消待续开。
- 一次性按键检测先独占 claim lock 再读取和移动请求；写结果失败时恢复请求，
  避免并发来源同时认领失败。

### 2026-08-24 迟到 F5 隔离与 Codex 权限核实

现象与直接原因：

- 真机出现首个电源键无反应、后续按键恢复，以及话筒会话结束后迟到 legacy F5
  干扰下一轮语音。直接 HID 已证明实体话筒键松开后，旧 F5 down/up 仍可能晚到；
  旧状态会把迟到 down 当成下一轮开始，把迟到 up 当成下一轮结束。
- 保存新映射与 F5 变换并发时，旧右侧 Alt 还存在只发 down、来不及发 up 的路径；
  `AudioStopped` 与已经通过变换检查但尚未发送的 F5 down 交错时，也可能出现先
  收尾、后补发 down。
- 最终复审又稳定复现一条双触发顺序：F5 变换已经返回目标、但右侧 Alt 尚未
  真正发送时，direct HID down 可以先发送当前配置快捷键，随后 F5 emit 再发送
  一次。旧代码会得到两个 down、一个 up，同一次实体按下可能被宿主执行两次。
- 新建文档可识别而当前 Codex 不能开启或上屏已另行确认是权限隔离：当前
  Codex/ChatGPT 为高完整性级别，搜狗为中完整性级别且 `UIAccess=0`。搜狗对权限
  更高的前台窗口返回 `PERMISSION_ELEVATION_REQUIRED` 后停止文字输入；这不属于
  Remote Mic PCM 故障。

修复范围：

- direct HID 明确松开而旧 F5 仍处于 down、待发送或变换会话状态时，把 legacy F5
  来源隔离到下一次成功重连；迟到 down/up 只清理旧来源，不再开启或关闭新会话。
- `_legacy_f5_state_lock` 统一串行化 F5 变换与发送、隔离判定、语音设置空闲判断与
  应用，以及 `AudioStopped` 收尾，避免保存映射和音频停止跨过一个半完成的按键对。
- 物理 HID 先认领手势且发现 F5 仍在“已决定、未发送”状态时，立即隔离该 F5，
  再走当前配置快捷键；若 F5 已先完成发送，则现有 transform session 让 HID 不再
  重发。两种顺序都只有一个正式发送者，不等待低层键盘钩子。

### 2026-09-03 方向键单次归属、单进程生命周期与预授权 HID 助手

- 已确认根因：Windows 会先把 RC003 原始方向键送给前台，Raw Input 随后才到达无线麦；
  旧实现又按映射发送一次方向键，所以安装后同一次短按可能执行两次。管理员权限本身不
  消除双触发，只是让更早的 HID tap 可用，从而有机会在原始键到达前认领和抑制它。
- 当前方向归属改为只接受 HID tap 执行自定义单击、双击、长按和遥控器组合；Raw Input
  方向事件不执行映射，也不再迟到地武装抑制器。HID tap 异常时 Windows 原始方向继续
  正常通过，不会再叠加无线麦映射；其它非方向按键沿用现有降级行为。
- HID tap 从 `READY` 失联时，旧实现可能已经接收最后一个按下却收不到对应抬起。本批
  在同一个输入仲裁锁内取消当前组合、单击/双击/长按和重复状态，并把仍按住的键锁到
  真实松开或后续中性报告；不再把异常断线伪装成一次正常松开，避免误触单击、连续移动
  或旧长按计时串入下一次按键。
- HID 接管启动时先等待中性报告，再截获后续完整按下/松开；接管切换和 Raw Input 设备
  移除会取消半截手势。Windows 原始按下已经放行时会主动补发对应松开，补松与新动作在
  同一串行锁内执行；设备移除后请求重连，避免断线时留下系统按键或本地手势状态。
- 单击、双击、长按和按住重复的每个计时器都有独立代次和令牌；已取消的旧计时器即使
  线程晚到，也不能触发新一轮按键。重复动作执行较慢时，真实松开仍可立即撤销当前按住
  令牌，动作返回后不会继续排下一次重复。
- 桌面生命周期收敛为每个 Windows 登录会话一个长期主进程：Qt 窗口、通知区域、桥接
  worker 和元素导航都由该进程持有。重复启动只唤出已有窗口；`--bridge` 是兼容启动
  形式，命中已有主进程时只写入短时启动请求。桥接 worker 继续持有旧桥接 mutex，防止
  升级期间历史独立桥接同时占用 BLE、Raw Input、HID、合成按键或音频。
- 设置页启动桥接前会先停止自己持有的旧进程句柄；句柄已失效时继续检查旧桥接 mutex，
  不再被失效句柄挡住迁移。具有托盘控制入口的旧桥接走正常退出；无法安全识别和控制的
  更老实例只明确提示用户手动退出，不按模糊 PID 强杀。
- 元素导航正常路径嵌入桌面 Qt 事件循环，按键 worker 只提交开关请求，不再创建长期伴随
  进程；旧隐藏入口保留兼容。右 Alt 物理化钩子使用可写 `MSG` 缓冲建立消息队列，避免
  空指针调用；私有注入标记迁到 `voice_key_physicalizer_windows.py` 单一来源。
- 元素导航和快捷键录制只吞掉自己已经接管过的松键；启动钩子前已经按住的键，其重复和
  松开继续交给原窗口。实体键与无线麦注入键分开记账，导航关闭、菜单放行或两类同名键
  交错时，不会把下一次实体方向键错误放行或把原窗口的键锁住；消息队列建立后才报告钩
  子就绪，启动后立即退出也能可靠卸载。
- 安装版新增独立 one-file HID 助手。安装器和桌面程序保持普通权限，安装后只为助手
  请求一次 UAC；助手复制到 Program Files，并登记固定名称、固定路径、固定 `--inject`
  参数、无登录触发器的按需计划任务。桥接每次只请求运行该任务，任务内自行定位并核验
  当前 RC003 WUDFHost；调用方不能传 PID、程序路径或用户配置。
- 桥接调用前会核对安装目录内助手与受保护副本的 SHA-256、当前用户 SID 和完整任务
  XML；任务或文件不符合合同时拒绝使用。设置页在安装版中显示明确异常和“修复权限”，
  修复成功后正常重启运行中的桥接；卸载在删除程序文件前先经 UAC 删除任务和助手。
- 权限边界：该方案要求当前登录账号本身属于管理员组。标准账号在 UAC 中输入另一管理员
  账号密码时，任务归属另一个账号，不能成为当前标准账号的无提示管理员入口。便携版和
  源码运行不安装预授权任务，仍需显式从管理员环境启动才能使用自定义方向映射。
