# BUG-023：松手上屏后宿主语音窗口仍停留

状态：兼容选项已实现，默认关闭，待当前候选真机复测。

## 现象

RC003 按住说话已经能产生语音数据并让宿主上屏，但部分宿主在话筒键松开后
只完成文字提交，语音窗口仍保持打开，需要再点一次宿主快捷键才能退出。这个
现象与遥控器是否继续传声是两件事：遥控器松手后音频已经停止，剩下的是宿主
界面的结束方式。

## 设计边界

- 不能把该问题重新包装成“开关型语音”；RC003 松手后不会继续传声。
- 不能默认补发，因为有些宿主在 key-up 时已经正确关闭，再补发可能反而重新
  打开语音窗口。
- 补发只能属于本次成功开始的按住会话；热键发送失败、断线或清理时不能误发。

## 修复

- 新增默认关闭的“松手后再触发一次”选项。
- 话筒松手时先发送 key-up，不让右 Alt 或其他快捷键保持按下。
- 若随后收到设备音频停止，约 120 毫秒后点按一次本次会话快捷键；若设备未
  报音频停止，约 800 毫秒后最多兜底一次。
- 新话筒按下、设置变化、断线和清理都会取消旧计时器。
- 补发使用本次会话的快捷键快照；中途修改设置不会改变已经排队的结束动作。
- 部分输入失败时保留安全释放状态并请求重连，普通发送失败只记录日志，不
  反复重试而造成宿主状态翻转。

## 自动验证

- 默认关闭时不补发。
- 音频停止后补发一次；没有音频停止时兜底一次。
- 重复音频停止不重复补发。
- 新按下和连接清理会取消。
- 使用会话快捷键快照。
- 不完整发送保留安全释放并触发重连。

## 真机复测

1. 关闭该选项，连续完成 5 轮按住说话，记录宿主是否自行关闭。
2. 开启该选项，再连续完成 5 轮；预期松手后文字上屏且宿主窗口关闭，不重新
   打开，不出现时间日期，不残留右 Alt。
3. 开启后快速连续进行两轮，确认上一轮计时器不会落入下一轮。
4. 分别测试宿主“直接上屏”和“先润色再上屏”设置，记录二者是否需要不同等待。
