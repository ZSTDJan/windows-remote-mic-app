# BUG-023：松手后补发宿主快捷键没有实际收益

状态：兼容方案已撤下；产品只保留标准按住开始、松手结束。

## 现象

RC003 按住说话已经能产生语音数据并让宿主上屏，但部分宿主在话筒键松开后
仍保留语音窗口。schema 2 曾增加默认关闭的“松手后再触发一次”，尝试在正常
抬键后再点按一次同一快捷键，帮助宿主关闭或提交窗口。

## 后续证据

- 2026-08-23 下午的有效运行日志记录了多轮非零语音数据，证明新版按住说话
  链路和音频转发已经运行。
- 同一日志也多次记录补发动作已经排队并实际发送。用户仍没有得到预期结果，
  因而问题不是“选项没执行”，而是这次额外点按对实际宿主没有可靠收益。
- 额外点按还依赖宿主当前状态：宿主若已在正常抬键时结束，再点一次可能重新
  打开窗口、切换模式，或落入下一轮输入。

## 最终处理

- 删除设置界面的“松手后再触发一次”。
- 删除配置字段 `voice_release_finish_tap_enabled`；配置升级到 schema 3，加载或
  保存旧文件时都会移除该字段。
- 删除运行时计时器、延迟补发和跨会话取消逻辑。即使内存中仍出现旧字段且值为
  `true`，也不会再发送额外点按。
- 话筒键只执行标准按住说话：按下发送一次快捷键按下，实体松手或音频停止发送
  一次快捷键抬起，后到的结束事件不会重复发送。

## 自动验证

- 覆盖实体松手先到、音频停止先到两种顺序，均只有一次按下和一次抬起。
- 覆盖旧字段为 `true` 时绝不调用额外点按。
- 覆盖默认配置、旧配置加载、配置保存和设置页保存都不再保留旧字段。
- 真实离屏 QML 加载确认旧开关对象不存在且无 QML 警告。

## 真机复测

1. 明确把话筒键设为“按住说话”，保存并启动桥接。
2. 连续完成 10 轮按住说话，包含快速开始下一轮和宿主润色模式。
3. 确认每轮仅在按住期间传声，松手后不残留右侧 Alt、不插入日期，也不出现
   额外一次快捷键造成的窗口重新打开。
4. 宿主窗口是否在标准抬键后关闭属于宿主快捷键语义，需用实体键盘先验证；
   本程序不再通过第二次点按猜测宿主状态。
