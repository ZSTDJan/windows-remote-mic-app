# BUG-004 后台桥接缺少可见退出入口

状态：已通过本机人工验收

记录日期：2026-08-20

## 现象

设置窗口与桥接进程分离。用户从设置页启动桥接后关闭设置窗口，后台桥接
仍会继续运行，但 Windows 桌面没有提供可见的桥接状态和退出入口，容易误以为
软件已经关闭。便携版还需要借助任务管理器结束进程。

## 根因

- 关闭设置窗口只结束 PySide6 设置进程，这是原有的有意设计；遥控器桥接由
  独立的 `--bridge` 进程持有。
- 后台进程只有单实例互斥锁和日志，没有 Windows 通知区域图标或菜单。
- 因而问题不是普通任务栏按钮缺失，而是独立后台进程缺少可发现、可控的
  生命周期入口。

## 修复设计

- 保留设置窗口与桥接进程分离，避免用户调整设置或关闭窗口时意外中断遥控器。
- 桥接进程创建原生 Win32 通知区域图标，不引入新的托盘第三方依赖。
- 双击图标或右键选择“打开设置”时，用参数数组启动当前程序的
  `--settings` 入口，不经过 shell。
- 右键选择“退出桥接”时，把退出请求投递回 asyncio 主线程，取消桥接运行
  任务，并进入现有 BLE、HID、语音热键、音频和单实例锁清理流程。
- Explorer 重启后重新注册图标；托盘初始化失败只记录日志，不阻止桥接
  原有功能运行。

## 验证门槛

- 托盘消息循环可创建和停止，不残留线程或图标资源。
- 双击和“打开设置”只启动设置入口，不递归启动第二个桥接。
- “退出桥接”会取消桥接任务并调用应用停止逻辑，不直接强杀进程。
- 冻结候选中图标可见；从菜单退出后进程消失，日志包含退出请求和既有清理
  记录。
- 关闭设置窗口后桥接仍运行，行为与文档一致。
