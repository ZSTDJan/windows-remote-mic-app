# BUG-026：桥接存活状态过期与首次按键就绪循环等待

状态：代码已修复，自动检查通过，待构建本机候选并进行真机复测。

## 复核入口

本项来自 `hold3` 修改完成后的一般自检。检查范围不是只看差异，而是完整重读
`SettingsController` 的桥接状态、真实按键检测和停止函数，继续检查 QML 调用点、
补充通道状态机、同类按键表以及正反例。

## 确认问题

### 设置窗口中的桥接状态会过期

明确路径：

1. 桥接运行时从通知区域打开设置窗口。
2. 设置窗口初始化时记录 `bridgeRunning=True`。
3. 从通知区域选择“退出桥接”；桥接进程结束，设置窗口按既定设计继续保留。
4. 旧代码没有定时刷新或退出通知，两个页面的红色警告继续隐藏。
5. 此时按话筒键，后台实际已经不存在，原始按键仍可能进入前台并输入日期或时间。

直接原因是桥接状态只在窗口初始化、开始真实按键检测和“保存并启动桥接”三个入口
更新。页面只绑定属性，没有持续刷新。开始按键检测虽然能刷新布尔值，但不会同步
历史启动文字，界面可能同时显示旧的“正在运行”和新的红色警告。

### 补充通道提示要求用户循环等待

明确路径：

1. 本地真实按键检测启动，补充通道完成连接并进入“等待首次设备读取”。
2. 旧界面要求用户等待“补充按键通道已就绪”后再按键。
3. 底层只有收到第一次有效设备读取才会进入“已就绪”；连接握手和心跳不会进入。
4. 用户遵照提示不按键时，状态无法前进。本地检测又没有 60 秒超时，会无限保持。

同类检查还确认：Windows 按键通道启动失败而只剩补充通道时，旧检测回调只接受
返回和音量键；上、下、左、右等其余已知按键会被丢弃。底层补充通道实际提供完整
已知按键表，因此这是设置页局部过滤错误，不是硬件能力边界。

## 修复

- 主窗口保留唯一一个桥接状态刷新计时器；窗口可见时每两秒检查一次，重新激活时
  立即检查。两个页面继续共用同一 `bridgeRunning` 属性，不重复查询。
- 桥接当前存活状态与最近一次明确启动结果分开处理。定时刷新会更新红色警告，
  但不会覆盖启动失败原因或已启动 PID；启动成功文字改成历史时点描述，避免桥接
  后来退出后仍声称“目前正在运行”。
- `startKeyDetection()` 复用同一个桥接状态检查，不再保留第二套读取逻辑。
- 补充通道进入“已连接、等待首次设备读取”时，界面明确要求现在直接按一次；
  第一次包含已知按键的有效读取会同时完成通道确认和按键捕获，不需要第二次。
- 本地检测和后台桥接检测统一使用 60 秒超时；停止资源失败时保留具体停止错误，
  不用普通超时文字覆盖。
- 设置页补充通道检测改用界面支持的 13 键完整表。仅补充通道可用时，上键等
  普通已知键也能被选中；空报告、未知按键值、界面未提供的静音值、错误报告
  编号或长度不会误判。

## 真机复测

1. 启动桥接并从通知区域打开设置；保持设置窗口不关，从通知区域退出桥接。确认
   最迟两秒内连接页和按键页都出现红色警告，最近一次启动结果仍保留为历史描述。
2. 在桥接未运行时开始真实按键检测。补充通道显示“已连接”后，直接按一次返回键
   或音量键；确认第一次就被捕获，不需要先等“已就绪”或再按第二次。
3. 人为让 Windows 按键通道不可用时，使用仅补充通道分别测试上键和返回键；两者
   都应一次捕获。等待超过 60 秒不按键时，检测应自动结束并释放资源。
4. 重新“保存并启动桥接”，完成 13 键逐键检测和三轮按住说话；确认不输入日期或
   时间。以上真机步骤未执行前，本项状态保持“待复测”。
