# BUG-014 切换续开后的 F5 回声立即关闭语音

状态：自动验证通过，`fix14` 待本机真机复测

记录日期：2026-08-21

代码修复提交：`bfd514d`

## 现象

用户在 `fix13` 使用“按一下切换”时，第一次短按并松开后仍不能稳定讲话；
必须先长按，使原始物理会话持续产生 PCM，才可能得到识别文字。

同轮测试确认语音可在记事本上屏，因此 RC003 解码、CABLE Input / Windows
WASAPI 和搜狗识别链并非整体失效。问题集中在程序主动续开后的几十毫秒。

## 本机日志证据

2026-08-21 17:44:58：

1. 17:44:58.114 实体松键完成，程序续发 `MIC_OPEN`；
2. 17:44:58.141 收到续流 `AudioStarted`；
3. 17:44:58.176 又收到 legacy F5 down，距续开约 62 毫秒；
4. 该边沿被当成第二次点击，17:44:58.733 发送 `MIC_CLOSE`；

随后立即关闭并得到空 PCM。相比之下，原始长按会话分别得到约 5.3 至 7.7 秒

## 根因

`fix12` 已把 `MIC_OPEN` 延后到实体 F5 up 之后，解决了“续开早于松键”。但
真机进一步表明，程序发送 `MIC_OPEN` 后约 60 毫秒还会出现一组新的 legacy
F5 down/up。旧状态机已经结束原手势，因此把这组紧邻续开的边沿认作用户的
第二次点击，刚打开的持续语音随即被关闭。

正常的第二次点击发生在用户讲话之后，日志中可与续开相隔数秒。不能永久忽略
下一组 F5，也不能扩大为长时间禁用按键。

## 修复设计

- 每次 TOGGLE 主动续发 `MIC_OPEN` 前开启 250 毫秒的回声保护窗口。
- 保护窗口内到达的物理 mic down 按来源登记为续开回声；对应 up 也成对吞掉，
  不改变语音状态和跨来源手势。
- 超过保护窗口的下一次按下仍按真实第二次点击处理，发送宿主关闭快捷键和
  `MIC_CLOSE`。
- 连接清理和真实关闭都会清除保护状态，旧来源不能串入下一代连接。
- 保护只在 TOGGLE 已处于 active 且刚主动续开时生效，不改变 HOLD 路径。

## 真机复测门槛

1. 使用 `fix14`，选择“按一下切换”和实际搜狗免按快捷键。
2. 第一次只短按并完全松开，不先长按；随后直接讲话。
3. 日志应出现 `toggle reopen echo` down/up 被忽略，之后持续产生非零 PCM，
   不得立刻出现 `toggle closing` 和空会话。
4. 讲话后再短按一次，必须正常结束。连续至少 5 轮并记录失败次数与启动延迟。
