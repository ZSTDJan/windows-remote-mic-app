# BUG-025：桥接未运行与冷启动就绪状态提示不足

状态：代码已修复，定向自动检查通过，待 `hold3` 构建与本机真机复测。

## 现象

- 2026-08-23 约 17:58，第一次检测上键没有反应；部分按键有延迟或需要按第二次。
- 同时按住话筒键没有唤起语音，只向前台输入了时间；任务栏通知区域没有桥接图标。
- 约 18:01 重新点击“保存并启动桥接”后，真实按键延迟消失，按住说话恢复正常。

## 日志结论

- 17:52:51 至 17:55:39，旧桥接多次检查两个 RC003 候选，均不可达；17:55:41
  正常退出。17:57 至 17:59 没有桥接运行记录，与任务栏没有桥接图标一致。
- 18:00:37 新桥接启动，18:00:45 确认唯一可达候选，18:00:47 取得语音能力并
  启动补充按键通道。补充通道在 18:00:48 连接关闭，18:00:50 重新附加，
  18:01:23 首次验证就绪。
- 18:01:23 上键被捕获，处理耗时约 2 毫秒；随后 13 个已知按键均被快速捕获。
- 18:01:48 至 18:01:52、18:01:59 至 18:02:06 两轮语音分别收到 244 帧和
  476 帧，汇总为有效信号。18:01:56 的一次过短操作为 0 帧，不代表整条链路失效。

## 根因

- 桥接未运行时，程序不能拦截话筒键、发送宿主语音快捷键或转发 RC003 音频；
  原始按键会进入前台应用，因此出现时间输入。这不是按住说话链路在运行中失效。
- 设置页本地检测会先启动 Windows 可直接识别的按键通道，再异步连接补充通道。
  旧界面在补充通道尚未就绪时就宣称两条通道都在监听，用户容易过早测试返回、
  音量等依赖补充通道的按键。
- 后台桥接的一次性按键检测原先只等待 15 秒，短于本次约 46 秒的冷启动就绪时间。
  这不是 17:58 本地检测的直接超时原因，但会在桥接刚启动时制造相同的“第一次
  超时、第二次才成功”体验。

## 修复

- 设置控制器在窗口打开时检查桥接进程；连接页和按键页在未运行或无法确认时显示
  红色警告，明确话筒键不会由本程序触发语音，要求先保存并启动桥接。
- 启动成功提示新增“首次连接和补充按键通道就绪可能需要约一分钟”，仍不把进程
  存活写成 RC003 已连接。
- 后台桥接按键检测等待由 15 秒延长为 60 秒。
- 本地检测启动时分别显示“Windows 按键通道已启动”和“补充按键通道正在连接”；
  只有收到真实就绪状态后，才显示“两条按键通道均已就绪，13 个已知按键均可检测”。
- 保持现有产品边界：打开设置窗口不会自动启动桥接，仍由用户明确点击
  “保存并启动桥接”。

## 真机复测

1. 先退出桥接并打开设置，确认连接页和按键页都显示红色未运行警告。
2. 点击“保存并启动桥接”，确认状态提示首次连接可能需要约一分钟；不要重复点击。
3. 立即点击“检测真实按键”，确认检测可持续等待；看到“两条按键通道均已就绪”
   后，逐一测试 13 个按键，每次只按一次。
4. 在记事本或目标输入框按住话筒键讲话再松开，确认出现识别文字、不再输入日期或
   时间；再连续测试 3 轮短句。
