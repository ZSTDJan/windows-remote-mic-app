# BUG-015 搜狗语音可向记事本上屏但不能向 Codex 输入框提交

状态：权限原因已确认；普通权限 Codex 待人工复测，Remote Mic 无代码修改

记录日期：2026-08-21

## 现象

同一轮 RC003 语音测试中，搜狗能够识别并把文字提交到新建文档，但当前
Codex 输入框中不能正常开启或提交文字。

## 当前边界

Remote Mic 只负责两件事：向当前前台宿主发送配置的搜狗语音快捷键，以及把
RC003 PCM 播放到 CABLE Input。识别后的文字属于搜狗进程；本程序不接收识别
结果，也不直接向目标输入框写文字。因此 `app.log` 可以证明快捷键、PCM 和
设备状态，不能证明搜狗最终向哪个控件提交了文字。

新建文档能够上屏已经证明音频链和搜狗识别本身可用。2026-08-24 对当前进程
权限做只读核实后确认：Codex/ChatGPT 及其父进程为高完整性级别，搜狗语音主
进程为中完整性级别且 `UIAccess=0`，记事本同为中完整性级别。搜狗安装包中的
`TextInputWorker.js` 会检查前台窗口权限；普通权限搜狗面对管理员权限目标时
返回 `PERMISSION_ELEVATION_REQUIRED`，随后不执行文字输入。

因此本机现象有明确触发路径：管理员权限 Codex 获得焦点 -> 普通权限搜狗
检测到目标权限更高 -> 搜狗拒绝向该目标输入。记事本与搜狗权限相同，所以同一
语音链可以上屏。这不是 RC003 PCM、Remote Mic 快捷键状态机或 Codex 文本控件
格式造成的已确认故障。

## 后续验证

1. 退出当前管理员权限 Codex 后，以普通权限重新启动 Codex。
   不要从管理员权限的 Remote Mic 桥接或其它管理员程序启动；当前应用启动动作
   使用普通子进程创建，子进程会继承父进程权限。
2. 让 Codex 输入框获得焦点，先用实体键盘触发同一搜狗语音快捷键并讲话。
3. 键盘路径成功后，再用 RC003 走同一轮按住说话，确认快捷键、PCM 和文字上屏。
4. 只有普通权限 Codex 下键盘成功而 RC003 失败时，才另行检查 Remote Mic 的
   快捷键交付与焦点时序。

本记录只登记原因和人工验证边界；未停止或重启任何程序，也未改变 Codex、搜狗、
Remote Mic 的权限、快捷键、音频设备或用户配置。

本记录不包含用户语音内容或输入框内容。
