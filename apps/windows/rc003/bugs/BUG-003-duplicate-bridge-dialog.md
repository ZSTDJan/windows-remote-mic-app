# BUG-003 重复桥接提示与状态矛盾

状态：检查点待实测

记录日期：2026-08-20

## 现象

设置页已经显示桥接进程已启动，再次点击“保存并启动桥接”时出现英文系统
提示 `another Remote Mic RC003 instance is already running in this Windows
session`；提示框后方却显示新 PID “目前仍在运行”。

## 根因

- 单实例保护正确识别了重复桥接，但重复子进程会先显示系统模态提示框，
  等用户点击后才以确定退出码 3 结束。
- 设置页的启动器只在约 1.5 秒内轮询子进程；模态框阻塞期间进程仍存活，
  因而被错误分类为新桥接已经启动。
- 这是启动结果观察与提示方式之间的竞态，不是第二个桥接真的绕过了保护。

## 修复设计

- 设置页构造桥接命令时附加隐藏的 `--bridge-from-settings` 标记。
- 只有该来源遇到已存在实例时静默跳过模态框，并保持原有退出码 3，供父
  设置页立即识别为 `ALREADY_RUNNING`。
- 用户直接运行 `--bridge` 时仍显示原有可见提示；互斥锁和失败关闭规则不变。

## 验证门槛

- 冻结与源码启动命令都携带隐藏标记，且不会递归打开设置页。
- 设置来源的重复实例不调用提示框并返回退出码 3。
- 普通 `--bridge` 重复启动仍调用提示框并返回退出码 3。
- 设置页最终显示“已经在运行”，不能把阻塞在提示框上的重复子进程写成
  “已启动”。
