# BUG-024：设置即时显示、未保存提示与旧语音配置误判

状态：代码已修复，自动检查通过，待 `hold2` 本机真机复测。

## 现象

- 编辑按键映射时，从单击、双击或长按下拉框选择动作后，可编辑输入框仍显示
  旧值；关闭编辑弹窗后才显示新值。
- 修改映射、语音快捷键、松手收尾、输出设备或设备选择后，窗口没有统一、
  醒目的“尚未保存”提示。
- 真实按键检测期间，补充按键连接临时关闭时，返回键、音量键等按键可能暂时
  测不到；旧提示直接显示内部通道名称，用户无法判断哪些键仍可测。
- 话筒键在前台只产生日期，长按也没有触发宿主语音快捷键。

## 核实结论

- 三个可编辑下拉框原先只把所选动作写入模型，没有同步自身 `editText` 和编辑
  弹窗中的当前值，因此输入框要等后续状态刷新才变化。
- 设置控制器原先没有统一的“界面值已不同于已保存文件”状态。
- 补充按键通道临时断开时，只剩 Windows 能直接识别的普通按键通道；通道恢复
  后，13 个实体键仍可完整捕获。这是临时通道状态，不是映射数据丢失。
- 被测机仍保存 2026-08-21 的 schema 1 开关型语音配置，话筒键映射也是旧语音
  动作；新版按产品边界拒绝自动转换，且当时没有后台桥接进程。原始话筒键因此
  进入前台应用并触发日期功能。该现象不是新版按住说话链路启动后失效。
- 用户提供的旧日志最后有效内部记录约为 2026-08-23 01:29，包含已撤下的旧专项
  程序和开关型代码，不能作为 `hold1` 最新程序的运行日志。历史专项结果
  `no_start_search` 只用于证明硬件边界，不能替代当前程序日志。

## 修复

- 三个下拉框在动作行被激活时立即同步可编辑文字、弹窗状态和映射模型；不用再
  点击“完成”才能看到新值。
- 新增统一未保存状态。主/次映射、按住说话快捷键、松手收尾、输出设备、设备
  选择和恢复默认发生实际变化时置为未保存；保存成功才清除，校验或写盘失败时
  保留。旧语音配置被停用、旧输出端点只在界面预选时也直接标记为待保存。
- 窗口底部用红色状态条显示“设置已修改，尚未保存。”；保存错误优先于该提示，
  保存成功后恢复普通成功信息。
- 旧语音配置保存错误显示“话筒键”，不再显示内部按钮代号。
- 按键检测提示改为“Windows 按键通道”和“补充按键通道”。补充通道关闭时明确
  说明返回键、音量键等可能暂时测不到，并提示等待“补充按键通道已就绪”。

## 真机复测

1. 打开任意按键的编辑弹窗，分别从单击、双击、长按下拉框选择动作；每次选择
   后输入框应立即显示新值，不点击“完成”也可看到。
2. 依次修改映射、按住说话快捷键、松手收尾和输出设备，确认底部持续显示红色
   未保存提示；制造一次保存错误时应优先显示错误，修正并保存后提示消失。
3. 启动真实按键检测。若提示补充通道暂时不可用，先测普通方向或确认键；等待
   通道就绪后再测返回键和音量键，最终确认 13 键完整可测。
4. 在设置页把话筒键明确选为“按住说话”，设置宿主实际使用的语音快捷键并保存，
   再点击“保存并启动桥接”。在前台输入框按住实体话筒键讲话，确认出现识别文字、
   松手释放且不再插入日期。
