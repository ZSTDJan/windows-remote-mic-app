# BUG-027：语音长按结束后按键或鼠标持续连按

状态：已修复并通过真机复测，2026-08-30 收口。

记录日期：2026-08-30

## 发生了什么

按住遥控器的话筒键讲话并松手后，下一次键盘输入有时会像按键一直没有松开：只按
一个字母，却连续出现很多个相同字母。鼠标偶尔也会出现类似的拖住或连按感觉，语音
结束后还可能短暂卡顿一下。

这个现象在搜狗和微信输入法中都出现过，也发生在远程窗口里，所以它不是某个输入法
的文字上屏问题，也不是粘贴动作本身造成的。

## 为什么会发生

遥控器的一次话筒键操作，会通过声音状态、实体按键和 Windows 转换出来的按键信号
分别报告给程序。这些信号来自不同位置，到达程序的先后顺序并不固定。

旧程序看到“声音已经停止”时，就认为整次话筒键操作结束了。但在真实设备上，实体
按键信号有时还在路上。这个迟到的“按下”随后被误认为是新一轮操作，程序又向语音
软件发送了一次快捷键按下，却等不到属于这一轮的快捷键松开。

结果就是 Windows 或远程软件认为某个键仍被按住，后面的字母、鼠标或快捷键操作便
可能连续触发。长按会让几路信号之间的时间差更大，所以更容易出现，但长按本身不是
另一个问题。

它和“Alt 键锁死”看起来很像，但触发条件不同：本问题发生在语音长按结束之后；
与语音无关的 Ctrl、Alt、Win 残留，仍按 `Alt键锁死问题.md` 排查。

## 怎么修好的

- 一次实体长按始终只算一轮语音操作，不能因为声音先停了就提前结束。
- 迟到的按键信号仍归入刚才那一轮，不能再开启第二轮。
- 程序只允许向语音软件发送一次快捷键按下和一次匹配的松开。
- Windows 转换出来的迟到 F5 只用于完成旧操作的清理，不能执行新动作，也不能影响
  下一次遥控器按键。
- 断开、重连或退出时，旧连接留下的信号必须作废，不能带入新连接。

## 怎么确认已经修好

- 两台机器的黑匣子都捕捉到了同一种错误顺序，因此根因不是猜测。
- 针对长按、信号迟到、下一轮按键、按键检测和断开清理的自动测试全部通过，完整测试
  和测试包自检也通过。
- 2026-08-30 用户使用修复后的测试包进行真机复测，确认语音长按结束后不再出现连续
  按键或卡键，本问题正式收口。

测试包的文件名、哈希和完整自动测试数字保存在 `TESTING.md` 的
`CHECK-VOICE-018`，这里不重复堆放。

## 以后再出现时怎么查

先确认问题是不是发生在“按住话筒键讲话并松手”之后。如果是，先保留证据，不要急着
重启程序，也不要先认定是输入法、UU 远程或剪贴板的问题。

需要记录：

1. 出问题的准确时间，尽量精确到秒。
2. 话筒键大约按了多久，当时使用哪个输入法和远程软件。
3. 松手后做了什么操作，是哪个字母连续出现，还是鼠标出现了异常。
4. 当时运行的程序版本，以及主控端和被控端对应时间的黑匣子压缩包。

后续 AI 应先读取本文件，再查看 `TESTING.md` 的 `CHECK-VOICE-018`、
`MAINTENANCE.md` 的“2026-08-30 迟到 HID 与 F5 跨轮残留修复”，以及修复提交
`e97b424`。只有新日志再次证明程序多发了一次按下却没有匹配松开，才重新打开本问题。

不要用无条件补发 Alt 松开、固定等待几百毫秒，或者“声音一停就立即结束整轮操作”
来掩盖问题，这些做法可能影响用户真实按住的键，或者让同一问题换一种方式复发。
