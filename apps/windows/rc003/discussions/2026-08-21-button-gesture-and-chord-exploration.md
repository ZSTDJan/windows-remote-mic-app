# RC003 按键手势与组合按键可行性讨论

日期：2026-08-21

状态：过程讨论，暂不实施

范围：Windows RC003 按键映射与设置界面

## 1. 文档目的

本文记录按键映射界面调整期间对单击、双击、长按、连续重复和跨按键组合的
阶段性推演，便于以后回忆为什么当前界面只保留既有手势，以及重新讨论组合
按键时需要先验证什么。

本文不是需求承诺、实现设计或真机验收记录。文中提到的跨按键组合目前没有
进入配置格式、运行时分发、设置界面或候选包，不能据此声称软件已经支持。

## 2. 当前实现事实

当前正式动作模型以一个逻辑按钮为单位，支持：

- 单击 `single_click`；
- 同一按键双击 `double_click`；
- 同一按键长按 `long_press`；
- 部分导航类单击动作在保持按下时自动重复。

`A -> A` 已经属于同一按键双击，不需要再增加一种“顺序组合”名称。配置了
双击动作后，单击必须等待双击判定窗口结束才能确认；这属于手势识别本身的
必要取舍，不是额外功能故障。

当前 `button_gesture.py` 为不同 `button_id` 分别保存手势状态。方向、返回和
音量类按键还可以由 `app.py` 判定为可重复动作；但当同一按键配置了双击或
长按时，保持按下、快速连点与次级手势之间存在天然语义竞争，不能同时假定
每一种解释都成立。

## 3. 已查到的协议与输入层能力

RC003 HID 按键报告的六字节负载包含三个 little-endian usage 槽位。现有
`hid_identity.py` 会把一帧解释为最多三个当前活跃 usage 的绝对快照，并通过
前后快照集合差生成按下和松开边沿。`raw_input_windows.py` 与
`frida_compat.py` 也保留活跃 usage 集合，而不是只保存最后一个键。

因此，协议格式和现有输入解码层能够表达、保留多个同时活跃的按键。现有测试
也覆盖了同一报告中同时出现两个已知 usage 的解码。

这仍不能证明 RC003 固件会对任意两个实体按键实际发出重叠报告。某些按钮还
可能走特殊的系统、媒体或语音路径。跨按键组合若重新进入范围，必须先用真机
报告探针验证目标按键对，不能仅凭三个槽位推断硬件已经支持。

## 4. 讨论过的跨按键组合

讨论的主要形式是“辅助键组合”：先按住 X 不松，再按下 Y，由 `X + Y` 触发
一个动作。它不是 `A -> A` 双击，也不是先松开 X 再按 Y 的顺序手势。

若以后实现，至少需要明确以下规则：

1. 只有已经显式配置的 `X + Y` 才能触发组合；
2. X 进入辅助状态后遇到未配置的 Y，不应突然退化为执行 Y 的普通动作；
3. 已成立的组合应消费本轮 X、Y 边沿，不能随后再补发两者的单击或双击；
4. 组合先只允许两个键和一个动作，不继续叠加组合双击、组合长按或三键组合；
5. 释放顺序、重复报告、未知组合和配置热更新都要有确定的收尾边界。

### 4.1 与长按的冲突

“长按 X”和“按住 X，再按 Y”拥有相同前缀。若 X 的长按超时已经触发，再按
Y 时软件无法撤回已经交付的动作。要求用户必须在固定毫秒数内补按 Y 虽然可以
形成优先级，但会产生明显的抢时操作和误触边界。

当时得到的无冲突方案是：一个按键只要被配置为辅助键 X，就禁止同时配置 X
自己的长按动作；X 的单击和双击仍可在没有进入组合时保留。这个方案只是推演
结论，尚未写入 schema、校验器或界面。

### 4.2 与快速连点和自动重复的冲突

- 配置双击后，两次快速单击必须被解释为一次双击，不能同时再解释为两次单击；
- 把方向键当作普通导航键时，更常见的需求是连续点按或按住自动重复；
- 给方向键配置双击会占用两次快速点击，给它配置长按会占用保持按下的语义；
- 自动重复应被视为单击动作的保持行为，而不是第四种可映射手势。

因此，方向、返回和音量类按键适合默认只保留单击并允许按住重复；双击和长按
可以存在于统一动作模型中，但不应默认替用户占用这些导航习惯。

## 5. 设置界面讨论结论

按键映射页倾向采用矩阵方式呈现：

`遥控器按键 | 单击 | 双击 | 长按`

方向、返回和音量类按键可显示“可连续”状态，但它表示单击动作支持按住重复，
不是新增的映射列或手势类型。

曾推演过增加“辅助组合”列，并在矩阵下方维护 `辅助键 | 配合按键 | 动作` 的
独立规则表。由于当前单击、双击、长按已经覆盖主要需求，而辅助组合还需要真机
报告验证、冲突策略、配置迁移和更多测试，本轮不把该区域加入正式界面。

## 6. 当前决定

- 当前功能范围保持单击、同键双击、长按和既有的导航类按住重复；
- 不新增辅助键、跨按键组合或任意顺序手势；
- 当前按键映射界面调整不为尚未实现的组合能力预留可操作入口；
- 本讨论不改变现有配置 schema、运行时行为、测试基线或候选包身份；
- 未来只有在单击、双击、长按不足以满足明确场景时，才重新打开组合按键议题。

## 7. 以后重新评估时的前置工作

1. 增加只记录逻辑按键和时间边沿的真机组合探针，不记录蓝牙地址、设备路径、
   设备令牌或输入内容；
2. 先验证普通按键与方向键的重叠报告，暂不从麦克风、电源和音量特殊路径开始；
3. 明确辅助键长按是否强制互斥，以及未配置组合的消费规则；
4. 设计独立 schema 迁移、配置校验、界面表达和热加载边界；
5. 覆盖按下顺序、释放顺序、重复报告、断连清理和与现有双击/长按定时器的竞争；
6. 真机验证通过后再更新主台账和用户文档，不能把协议槽位或自动测试当作硬件
   支持证明。
