## 3. Windows 当前已经具备的能力

以下能力不应被误判为“需要从原版重新引入”：

- RC003 连接、ATVV 语音解码、指定音频输出端点和后台桥接；
- 13 个实体按键的单击、同键双击和长按映射；
- 方向、返回和音量等适用动作的按住重复；
- 自定义键盘组合键录入；
- 打开 Codex、Claude、cmux、微信、Cursor、Slack、企业微信、网易云音乐、
  Chrome、Edge、Zed 和无线麦设置等固定应用动作；
- 蓝牙、音频、HID tap、VB-CABLE、桥接进程和日志等 Windows 专属诊断；
- 托盘入口、设置窗口和桥接进程分离；
- 音频增益已经是配置值，当前默认 `gain_db=10.0`，但尚未在设置界面开放。

Windows 当前没有：本地使用统计、任意 App 选择、映射方案、按前台 App 自动
切换、组合动作、文字回眸、MCP 读取、手机/网页接力和自动更新。当前已新增的
VB-CABLE 主动回环只验证本地虚拟音频通道，不是任意端点试听工具。

## 4. 功能评估与当前决策

### 4.1 原作者式设置框架与连接就绪摘要（明确考虑）

当前操作：用户在“连接”“权限”“检查与修复”之间来回查找设备、音频端点、
桥接状态和缺失前提。

建议变化：网页原型已选定 A 方案，采用左侧导航、单页大标题和连接页就绪摘要；
继续保留 Windows 的“连接、按键、权限、检查与修复”语义，但把当前设备、桥接、
语音输出和关键缺项集中显示。只在缺项所在位置提供对应操作，不改变后台行为。

实际影响：用户能先看懂“现在能不能用、缺哪一步”，不用把进程存活误认为
设备和语音链路已经正常。

新增成本：需要重新组织 QML 页面和共享控件，并覆盖四个页面、不同设备模式、
窗口尺寸、主题、错误和未保存状态。它是共享 UI 的 L2 工作，但不必修改配置
schema 或桥接协议。

建议：第一优先级，以 A 方案继续收敛独立网页原型；原型复用现有遥控器实物图，
按 `900 × 680` 默认尺寸和 `760 × 620` 检查点验证最宽页面，再决定正式 QML
信息架构与窗口约束。

### 4.2 连接页三步就绪检查（明确考虑）

建议只显示三项真实状态：

1. 已选择并找到目标设备；
2. 已选择且能打开语音输出端点；
3. 后台桥接正在运行。

“输入法已经能识别文字”不能由程序自动判定，必须继续标为手动验证，不能用
绿色勾选伪装成已完成。

这一功能可以优先复用现有设置控制器和诊断结果，不新增“引导已完成”持久化，
避免仅为页面进度再创建一套状态来源。

建议：与界面框架一起引入。

### 4.3 向当前选定端点发送测试音（已适配落地，待真机实测）

当前问题：Windows 能预检端点是否可打开，但用户仍难以区分“端点可打开”和
“VB-CABLE 到目标输入法的完整路由正确”。

实际变化：在“检查与修复”页加入“测试通道”，只接受当前已保存的
`CABLE Input`，并自动匹配同一音频接口下唯一的 `CABLE Output`。发送短扫频后
直接分析回录信号；播放期间禁止重复启动、保存端点和从设置页启动桥接。

用户以后操作：先选择并保存 CABLE Input、停止桥接，再点击“测试通道”查看本地
回环结果；无需先连接 RC003 或按实体话筒键，但之后仍要单独验证输入法文字上屏。

好处：能独立验证 Windows 音频路由，显著缩短 VB-CABLE 排障链路。

已承担成本：新增扫频生成与相关性判定、一次性音频测试子进程、超时终止、与自动
检查/保存/桥接启动的互斥，以及“本地通道通过不等于 RC003 和输入法通过”的提示。

当前结论：源码检查点和自动测试已完成；真实驱动阈值、其它监听程序影响和最终
文字上屏仍按 `TEST-VOICE-008` 验收。

### 4.4 本地使用统计（待决策）

建议第一阶段只记录：

- 每个逻辑按键成功执行的次数；
- 每次 RC003 语音会话的开始、结束和持续时间；
- 按日、周、全部范围汇总；
- 数据仅保存在 `%LOCALAPPDATA%\RemoteMic\RC003`，不记录语音内容、前台窗口
  标题、蓝牙地址、设备路径或用户输入内容。

用户能看到实际使用频率和语音时长，也能帮助判断某个实体键是否稳定触发。

新增成本：桥接进程是事件生产者，设置窗口是读取者，需要独立、原子、可恢复的
统计存储，不能让高频按键回调直接同步写磁盘。还要设计保留周期、清空入口、
损坏恢复和跨版本格式。因为引入新的持久数据路径，属于 L3，不能与纯界面调整
混在同一批实施。

当前判断：具备价值，但涉及新的持久数据路径和 L3 影响。是否立项、记录范围、
保留周期和清空方式均待用户后续决策。

### 4.5 关于与帮助页（明确考虑）

第一阶段可以提供版本号、项目主页、许可证/第三方说明、日志目录、安装与使用
说明入口，以及“不保存语音内容、不自动修改默认音频设备”的实际边界。

暂不加入自动更新、预发布通道、Dock 设置等 macOS 专属或尚无 Windows 发布基础
的功能。

建议：可随正式界面重排一起引入，成本和风险较低。

## 5. 技术上可以引入，但当前待决策

### 5.1 任意 App 动作（待决策）

Windows 已经支持一组固定 App 动作，因此可以继续扩展为用户选择本机 `.exe`
或快捷方式，并保存明确路径。相比继续增加固定名单，这更符合实际使用。

但它会引入文件选择、路径持久化、程序升级后路径失效、参数注入、网络路径、
签名和不存在目标的处理。第一版应只允许用户主动选择本机现有可执行文件或
快捷方式，不接受任意命令行、脚本、参数和工作目录。

建议：在界面结构稳定后单独引入；不与“任意脚本执行”合并。

### 5.2 可调语音增益（待决策）

Windows 已经通过配置和解码链支持增益，技术上可以增加滑块。问题不是能否
调，而是过高增益会放大噪声并造成削波，用户还需要测试音或真实语音反馈才能
判断数值。

建议先完成真实 VB-CABLE 阈值和实际电平验证，再评估是否开放有限范围，例如保留当前
`10 dB` 默认、提供重置，并明确它只调整 RC003 解码后的输出，不调整系统麦克风
和 DJI Mic 2。不要直接照搬 macOS 当前显示范围。

### 5.3 多套按键映射方案（待决策）

建议拆成两阶段：

1. 先支持用户手动创建、命名和切换完整映射方案；
2. 再评估按前台 App 自动匹配。

第一阶段已经需要配置 schema、默认方案、删除与重命名、热加载和旧配置迁移；
第二阶段还需要可靠识别前台进程、处理管理员权限差异、UU 远程场景、应用升级
和未匹配时回退。两阶段都属于 L3。

建议：有明确“同一遥控器在多个 App 中需要完全不同键位”的真实需求后再做；
不要为了还原原版截图提前加入空入口。

### 5.4 组合动作（待决策）

原版的组合动作是按顺序执行多个受支持步骤，不等于任意脚本。Windows 若引入，
第一阶段也应只允许已有安全动作的有限序列，并定义延迟、取消、失败停止、按键
松开、重复触发和配置热更新规则。

它会放大输入注入、应用启动、窗口焦点和长按状态之间的竞态。当前单动作、双击、
长按和语音链路尚有真机验收项，不适合现在叠加组合动作。

建议：后置到统计、任意 App 动作和映射方案稳定之后。

## 6. 存在重要前置条件，当前待决策

### 6.1 文字回眸（待决策）

macOS 原版能通过辅助功能读取目标输入控件在语音会话前后的文字快照，再保存
确认新增的文本。Windows 当前只负责把音频送到第三方输入法和注入快捷键，无法
可靠知道最终识别文字，也不拥有目标输入框内容。

若强行实现，需要 UI Automation、剪贴板监听、键盘记录或自带 ASR 等新边界，
会增加权限、兼容、隐私和误记录风险。当前不应仅为了对齐原版功能而引入。

### 6.2 本地 MCP 访问（待决策）

MCP 读取依赖可信、可管理的回眸数据。Windows 当前没有可靠文字来源，因此不能
先做 MCP 外壳或空授权页。只有回眸本身证明可行并完成隐私设计后才有讨论基础。

### 6.3 手机、Apple Watch 或网页接力（待决策）

这些能力需要新的网络协议、身份确认、信任设备、音频传输、服务器或独立客户端，
也会扩大防火墙、凭据和远程执行边界。它们不是 Windows RC003 当前核心问题的
低成本延伸。

建议保持在当前 Windows 仓库范围之外，除非以后有独立产品需求、协议和多仓库
协作计划。

### 6.4 多只 RC003 自动选择（待决策）

Windows 当前在发现多个同名候选时拒绝猜测，随后只在唯一可用候选成立时连接，
这是避免连错设备的安全边界。原版界面中的多设备卡片不能直接移植成自动选择。

只有出现真实多遥控器需求，并能提供不泄漏设备标识的稳定选择和保存方式时，
才重新评估显式设备选择。

### 6.5 自动更新（待决策）

Windows 当前仍是未签名候选，发布来源、签名、更新清单、失败回退和防降级机制
尚未形成稳定合同。现在增加自动更新入口会制造错误安全感。

建议在 Windows 正式签名和发布流程稳定后另行设计，不随关于页一起实现。

## 7. 当前承接边界

1. 网页原型以 A“原作者延续版”为当前基线，复用已有遥控器实物图和 13 键热点，
   使用 Windows 右上角关闭按钮，并以 `900 × 680` / `760 × 620` 做默认尺寸与
   最小检查点；B 方案不再继续演进；
2. 测试音已按 Windows 实际链路落地为显式 `CABLE Input → CABLE Output` 主动
   回环；当前是源码检查点待实测，不是任意端点试听，也不证明输入法文字上屏；
3. 本地统计、任意 App、增益调节、映射方案、组合动作、回眸、MCP、手机/网页
   接力、多设备选择和自动更新只保留现状分析，全部待用户后续决策；
4. 2026-08-26 的后续授权只覆盖第 2 项所需正式 QML、诊断、音频指标、测试和
   配套文档；未修改配置 schema，未构建或发布产物，其它候选功能仍未获实施授权。
