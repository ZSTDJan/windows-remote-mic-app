## 2. 当前总边界

Quicker 不是 Remote Mic 的核心依赖。没有安装、没有运行或协议调用失败时，只影响对应
的 Quicker 动作，不应阻断 RC003 连接、普通按键、电脑快捷键或语音链路。

当前分成两条彼此独立的对接线：

1. **动作启动**：已经进入主程序。RC003 的单键手势和受限遥控器组合可以执行一个
   `quicker:runaction:` URI。
2. **悬浮动作导航**：元素导航已经作为普通映射动作进入主程序，并由独立伴随进程
   识别和移动到可信的 Quicker 浮窗；Quicker 关联状态导出仍未完成，因此这不等于
   已经交付 Quicker 深度集成。

不得因为关联状态仍在研究，就把悬浮窗识别写成未实现；也不得因为基础浮窗导航已经
接入，就把 Quicker 状态导出、跨窗口关联或全部宿主实测写成已经完成。

## 3. 官方启动方式

Quicker 官方“从外部启动 Quicker 动作”说明：

<https://getquicker.net/kc/manual/doc/quicker-starter>

Remote Mic 当前采用官方 URI 形式：

```text
quicker:runaction:动作标识
quicker:runaction:动作标识?参数内容
```

官方将外部启动标为专业版功能。动作标识可以使用动作 ID、动作名称或动作库 ID；
名称和动作库 ID 存在重复时可能无法唯一确定目标，因此长期配置优先使用动作 ID。
URI 方式通过 Windows 已注册的 Quicker 协议启动，比直接调用 `QuickerStarter.exe`
多一次协议跳转，但不需要在 Remote Mic 中寻找安装路径。

官方说明特别提示不要以管理员身份运行 Quicker，否则可能无法访问 `quicker:` 协议。
Remote Mic 不负责启动、提权或降权 Quicker，也不会更改 Quicker 自身设置。

## 4. Remote Mic 的 URI 合同

正式实现入口：

- 校验和序列化：`../src/ovb_rc003/key_mapping.py` 的
  `normalize_quicker_uri()` 与 `ButtonAction`；
- 输入框解析：`../src/ovb_rc003/settings_ui.py` 的 `_display_to_action()`；
- 执行：`../src/ovb_rc003/action_executor.py` 的 `open_quicker_uri()`；
- 运行时分派：`../src/ovb_rc003/app.py` 的动作执行入口。

当前合同：

- 只接受 `quicker:runaction:`，不接受 `showmessage`、`settings`、`debugaction` 等
  其它 Quicker 协议，也不接受任意 URI；
- 动作标识不能为空，输入必须是单行文本，总长度最多 2048 个字符；
- URI 直接交给 Windows 注册的协议处理器，不经过 `cmd.exe` 或 PowerShell；
- 调用是发出即返回，不等待动作执行完成，也不读取 Quicker 动作返回值；
- 保存和配置回读时会再次校验，非法值不能悄悄进入运行时。

这条窄合同是安全边界。除非有明确使用场景和单独确认，不扩大为任意协议启动、命令行
执行或双向 API 集成。

## 5. 按键与组合映射

### 5.1 单键手势

可编辑的单击、双击和长按动作都可以填写 Quicker URI，触发时各执行一次。电脑快捷键
同样不因持续按住而定时连发，避免重复执行动作和修饰键释放不完整。

话筒键主动作设为“按住说话”时，双击和长按不可用；这是语音生命周期限制，不是
Quicker 的限制。其它按键不能传送语音，但可以配置普通动作、电脑快捷键或 Quicker
URI。

### 5.2 遥控器组合

当前只提供一层类似 Fn 的受限组合：

- 主键：TV、菜单、主页；
- 第二键：上、下、左、右、确定、返回、音量加、音量减；
- 组合动作：普通动作、电脑快捷键或 Quicker URI；
- 话筒、电源和主页+菜单配对组合不参与；
- 被选为组合主键后，该键不能再配置双击或长按。

组合命中时吞掉主键和第二键的单键动作；没有命中时，主键在松开后执行原单击。一次
按住主键可以依次触发多个已经配置的第二键。继续扩展组合范围前必须重新推演套娃、
原生键漏出、主键补发和抬键顺序，不能只增加界面选项。

## 6. 权限与失败边界

目前需要分别验证两种实际运行组合：

1. 普通权限 Remote Mic + 普通权限 Quicker；
2. 管理员权限 Remote Mic（用于 HID tap）+ 普通权限 Quicker。

Quicker 本身保持普通权限。第二种组合能否稳定由 Windows 协议处理器跨权限启动动作，
仍以 `TEST-KEY-005` 的真实操作和 `app.log` 为准，自动测试不能代替。

调用失败时应只报告当前动作失败，不自动改用 `QuickerStarter.exe`、shell 命令、模拟
快捷键或修改 Quicker 权限。增加降级路径会改变安全和权限边界，必须单独讨论。

## 7. 悬浮动作与元素导航

产品入口由 `../src/ovb_rc003/element_navigation_runtime.py` 在独立伴随进程中加载
`../scripts/element_navigation_prototype.py` 这一份算法来源。已确认部分 Quicker
`FloatButtonWindow` 只有 UI Automation 根节点，没有可直接导航的子控件；原型因此
只在窗口已经通过悬浮窗过滤、尺寸受限且内部没有其它目标时，把可信的小窗根节点补成
一个坐标目标。

### 7.1 可选状态快照

原型可以只读以下 JSON 快照：

```text
%LOCALAPPDATA%\RemoteMic\RC003\quicker-navigation.json
```

也可以通过 `--quicker-state-file` 或 `REMOTE_MIC_QUICKER_STATE_FILE` 指定。当前读取的
核心字段是窗口句柄、是否绑定、绑定进程名和可见状态。明确绑定当前软件的浮窗可以位于
主窗口之外；快照缺失或损坏时，原型只对与当前窗口重叠或横纵间隔均不超过 48 像素的
可信小型 Quicker 浮窗启用保守回退。

Remote Mic 当前不会生成这份快照，不读取 `quicker.db`，也不修改用户 Quicker 配置。
Quicker 侧的状态导出动作尚未制作，因此该合同仍是后续对接预留，不是用户必须配置的
现成功能。

### 7.2 当前未完成项

### 9.2 覆盖矩阵与结论

- **鼠标输出，足以独立实现**：`MouseInputStep` 对左、右、中、X1、X2 提供单击、
  双击、按下和抬起，对滚轮使用垂直/水平 `clicks`；实际委托给
  `WindowsInput.InputSimulator.Mouse`。点击把 down/up 组成同一 `SendInput` 批次，
  X1/X2 使用 `XDOWN/XUP + mouseData=1/2`，一格滚轮为 120。证据等级：官方确认、
  静态直接证据。
- **注入事件识别，足以独立实现**：Quicker 给自家键盘和鼠标注入写入固定
  `dwExtraInfo` 标记，低层 Hook 同时读取系统 injected flag 和该标记，从而区分真实
  输入、自家注入、其它软件注入以及笔/触摸。只有非注入事件更新真实按键状态，避免
  自家输出重新触发自身规则。证据等级：静态直接证据。
- **抢占所有权，足以独立实现**：鼠标 Hook 分别记录真实按下状态、已捕获按下状态和
  处理状态。处理抬起时，如果某处理器想吞掉抬起、但对应按下并未由 Quicker 捕获，
  Quicker 会撤销本次吞键，防止只抢走半个按键序列。官方文档也明确：配置为触发键后
  该鼠标键会被拦截，不再传给当前窗口。证据等级：官方确认、静态直接证据。
- **状态恢复，部分足以独立实现**：键盘 Hook 维护真实按下时间并定期用系统状态清除
  已经松开的陈旧记录；停止 Hook 会清空状态。Quicker 另有“按键状态重置”工具，枚举
  当前仍被系统判定为按下的虚拟键并发送 KeyUp；官方 1.8.5 记录还说明动作执行结束会
  自动恢复动作开始前已经按下的修饰键。证据等级：官方确认、静态直接证据。
- **失败边界，需要改造**：随附 `WindowsInput.dll` 在 `SendInput` 返回数量不足时抛错，
  但没有显式补发可能缺失的 mouse-up；延迟键盘发送也可能在取消后停在中间事件。
  Windows 官方说明 `SendInput` 不会重置调用时已经按下的键，并可能受 UIPI 阻止。
  因此 Remote Mic 不照搬这一缺口，必须自己记录欠松开所有权、补发抬起，并在补松未
  确认前禁止新的输入注入。证据等级：官方确认、静态直接证据、高可信推断。

### 9.3 Remote Mic 采用规则

1. 普通鼠标映射只操作当前鼠标位置，不接管本机鼠标 Hook，也不改变元素导航算法。
2. 左、右、中、X1、X2 单击均以同一批次发送 down/up；滚轮一次发送一格。
3. 对部分发送或提交后异常，立即单独补发对应 mouse-up；补发仍失败时保留所有权，
   在下一动作、BLE 清理和最终退出前重试，未完成前拒绝新动作。
4. Remote Mic 目前只监听已识别的 RC003 输入，不需要拦截本机鼠标，也没有自触发
   环路；暂不引入全局鼠标 Hook 或 Quicker 的私有注入标记。
5. 动作名称中的“左键/右键”保持物理按键含义，与现有元素导航直接发送 Win32
   左键事件一致，不跟随 Windows 主次按钮交换设置。
6. 本轮只加入左/右/中单击、滚轮上/下、X1/X2；拖拽、仅按下、仅松开、横向滚动和
   一键双击后置，避免把持续所有权和新交互一起带入当前范围。

### 9.4 验收用例

- 每个鼠标按钮正常单击只调用一次 `SendInput`，顺序为 down 后 up；X1/X2 的
  `mouseData` 正确。
- 滚轮向上/向下分别发送 `+120/-120`，不产生需要清理的按下状态。
- 单击仅发送 down 时，立即补发一次 up；补发成功后报告动作失败但不保留所有权。
- 单击提交异常且补发失败时，应用保留具体鼠标键；下一动作先重试补松，失败则不执行。
- BLE 重连清理和最终退出均尝试补松，只有确认完成后才清除所有权。
- 七个动作可从单击、双击、长按和遥控器组合的统一动作列表选择、保存并回读。
- 旧程序读取含新动作的配置时可能停用对应映射；正式降级前需先改回旧版可识别动作。
