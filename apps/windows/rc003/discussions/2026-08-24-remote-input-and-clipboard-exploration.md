# 远程语音输入、Quicker 与剪贴板探索记录

日期：2026-08-24

状态：调查事实已整理；搜狗管理员重启入口、其它输入法对比和向日葵兼容方案均待后续实测与决策，暂不实施

范围：主控端 Remote Mic、搜狗语音输入、UU 远程、向日葵、Quicker 与被控端文字上屏链路

## 1. 记录目的

本文保存 2026-08-24 围绕远程语音输入所做的只读调查和现场测试，避免后续把已排除的判断重新当成结论。

本文不是实现方案、发布计划或配置修改授权。调查期间没有修改 Remote Mic、搜狗、UU、向日葵或 Quicker 的正式配置；后续是否增加功能，仍需结合实际使用和其它输入法对比单独决定。

## 2. 当前链路与已确认事实

### 2.1 UU 远程语音当前可用

- 2026-08-24 23:02 左右，用户通过主控端搜狗和 UU，成功把语音文字输入被控端 Codex。
- 被控端搜狗日志在该时段没有新语音记录，说明这次实际走的是“主控端搜狗识别 -> UU 传递输入 -> 被控端 Codex”，不是被控端搜狗识别。
- 因此，按当前成功链路，被控端不需要同时运行搜狗语音助手。
- UU 问题当日没有继续稳定复现，暂不把“UU 长期占用 Alt”或“UU 无法触发主控端搜狗”登记为已确认故障。

### 2.2 Quicker 不触发来自主控端黑名单

现场低层鼠标监控曾确认，主控端聚焦向日葵或 GameViewer 时，`右键 + X1` 的完整物理事件仍到达 Windows，但 Quicker 没有执行对应动作。

后续用户确认，主控端 Quicker 已主动把以下程序加入黑名单：

```text
SunloginClient.exe
GameViewer.exe
Enscape.RendererHost.exe
AweSun.exe
```

这解释了向日葵和 UU 窗口聚焦时主控端 Quicker 不执行动作。该行为是用户为了把鼠标操作交给被控端而保留的设计，不是远程软件拦截 Quicker 的故障。

此前“向日葵和 GameViewer 在应用层拦截鼠标，导致 Quicker 收不到”的判断作废。低层鼠标事件存在且 Quicker 无 `Execute task` 日志，只能证明动作未执行，不能在未知黑名单的情况下证明远程软件拦截。

### 2.3 搜狗管理员重启只解决本机高权限目标

用户转交的主控端日志显示：

- 22:00:29，普通权限搜狗尝试向管理员权限的 `RemoteMicRC003.exe` 上屏，被搜狗以 `INPUT_PERMISSION_ELEVATION_REQUIRED` 拒绝；
- 22:00:36，搜狗执行 `ime:relaunch-as-admin`；
- 22:00:37，新进程记录 `Current process elevated: true`。

这组证据只证明：搜狗权限低于当前本机目标窗口时，搜狗会拒绝上屏。目标是主控端本机的 `RemoteMicRC003.exe`，不能把这次结果直接扩展为 UU、向日葵或被控端 Codex 的远程链路结论。

对当前安装的搜狗语音组件 `1.0.1.3272` 做静态核验后确认：

- 权限不足时，搜狗语音浮窗显示“权限不足”；
- 用户点击浮窗中的“重启”按钮后，界面调用内部 `ime:relaunch-as-admin`；
- 主进程释放单实例锁，调用本机模块申请 Windows 管理员启动，成功后退出旧进程；
- 该入口由“重启”按钮点击触发，不是检测到权限不足后自动提权；
- 当前代码中没有发现设置页里的固定管理员开关或独立快捷键入口。

管理员权限由 Windows 批准，不是 Remote Mic 向搜狗授予。搜狗长期以管理员权限运行会扩大其麦克风、剪贴板和输入注入能力的权限范围，因此不能只因一次本机高权限目标失败，就默认把搜狗长期改为管理员运行。

### 2.4 向日葵粘贴旧内容的当前判断

对搜狗语音组件代码的静态核验确认：

- 默认文字提交策略是 `SHIFT_INSERT`；
- 流程是先通过 IPC 写入主控端剪贴板并等待本机写入确认，再立即发送 `Shift + Insert`；
- 向日葵 `AweSun.exe` 不在搜狗的特殊进程策略列表中，因此使用默认策略；
- 本机写入确认只代表主控端剪贴板已经更新，不代表向日葵已经把新内容同步到被控端。

主控端现场监控在 23:43:57.824 看到剪贴板已变为本次语音文字，但用户看到被控端粘贴了上一次内容。当前最符合现象的时序是：

```text
主控端剪贴板写入新文字
-> 搜狗立即发送 Shift + Insert
-> 粘贴按键先到被控端
-> 被控端仍读取旧剪贴板并上屏
-> 新剪贴板稍后才同步到被控端
```

这不是“录音文字还没生成就粘贴”，而是“文字已写入主控端，但尚未同步到被控端就执行了粘贴”。

向日葵官方资料和公开反馈能够证明远程剪贴板会受延迟、同步状态和其它剪贴板工具影响，但本次尚未找到与“搜狗写剪贴板后立即发送 Shift + Insert”完全相同的公开案例。当前机制高度吻合，仍需一次被控端毫秒级按键与剪贴板时间对齐，才能写成最终确认结论。

## 3. 已讨论但暂不实施的方案

### 3.1 搜狗管理员重启按钮

Remote Mic 可以考虑增加“以管理员权限重启搜狗”的辅助入口，但当前暂不实施，原因如下：

- 实际远程窗口 `AweSun.exe` 和 `GameViewer.exe` 当日均为普通权限，常规远程使用不一定需要管理员搜狗；
- 当前搜狗已经提供权限失败后的“重启”按钮；
- Remote Mic 若代为处理，需要识别搜狗安装路径、处理已有单实例进程并申请 UAC，增加外部软件兼容和升级风险；
- 用户还需要继续实际使用，并对比其它输入法后，再判断该入口是否真的有长期价值。

当前决策：保持“待决策”，不加入设置界面、配置格式或运行时。

### 3.2 拦截搜狗的 Shift + Insert

曾讨论由主控端 Remote Mic 监控剪贴板、拦截搜狗立即发送的 `Shift + Insert`，等待向日葵同步后再发送 `Ctrl + V`。

该方案技术上可以继续研究，但不作为当前首选：

- Remote Mic 目前只负责触发语音快捷键和转发音频，不接收搜狗识别文字；
- 当前按键抑制器有意放过软件注入事件，新增拦截会扩大公共按键链路的职责；
- 必须准确区分搜狗生成的粘贴与用户正常粘贴，否则可能吞掉真实键盘操作；
- 固定延迟受网络和向日葵同步状态影响，可能只是把偶发错误变成新的等待和误触发问题。

当前决策：暂不实施，不修改按键抑制器或剪贴板行为。

### 3.3 不依赖远程剪贴板的文字传输

更彻底的方案是让 Remote Mic 获取识别结果并把文字直接发送到被控端，不依赖向日葵剪贴板。这需要新增识别结果来源、跨机通信和被控端接收程序，已经超出当前“触发宿主输入法并转发音频”的边界。

当前决策：只保留为长期方向，不进入本轮实现。

## 4. 后续实测与决策项

1. 继续日常使用当前 UU 链路，观察主控端搜狗能否稳定向被控端上屏。
2. 如再次复现向日葵粘贴旧内容，在被控端同步记录 `Shift + Insert` 到达时间、剪贴板更新时间和实际上屏内容，确认是否确实为“按键先到、剪贴板后到”。
3. 对比向日葵窗口中的 `Ctrl + V` 与 `Shift + Insert` 行为，但在实测前不把任一方式写成正式修复。
4. 对比其它输入法的语音触发、文字提交方式、远程窗口兼容、权限要求和剪贴板依赖。
5. 完成一段实际使用后，再决定是否需要 Remote Mic 提供搜狗管理员重启入口，以及该入口是否值得承担外部程序路径、单实例和 UAC 兼容成本。

## 5. 结论边界

- 已确认：UU 当前成功链路使用主控端搜狗；Quicker 不触发来自主控端黑名单；搜狗管理员重启由权限错误浮窗中的“重启”按钮触发。
- 高度吻合但待最终确认：向日葵旧内容上屏来自粘贴按键快于远程剪贴板同步。
- 待决策：Remote Mic 是否增加搜狗管理员重启按钮。
- 待对比：其它输入法是否能减少管理员权限、快捷键注入或远程剪贴板依赖。
- 暂不实施：搜狗粘贴按键拦截、固定延迟补丁和跨机文字直传。
